```
  수도광열비    / 적요 "전기요금"
  기타운영비    / 적요 "잡비"
  복리후생비    / 적요 "간식"

유지 (INCLUDED)
  교육훈련비지원 · 특별교육훈련비              ← 이름이 비슷해도 빠지지 않음
  "직원 교육비 지출" · "외부 강사료 지급"       ← 낱말만으로는 안 빠짐
  "출장 하루 렌터카" · "출장 1박2일 렌터카"
  "출장 2박3일 렌터카" · "장기 임차이나 단발성 출장"
  「민원 담당자 교육…」 2행                    ← 적요만으로 일괄 제외 안 함
```

⭐ **기간 임계값 규칙이 없다는 것이 실제로 확인되었다.** 하루짜리도 2박3일도
자동으로 빠지지 않고, 장기 임차 표기 역시 자동으로 빠지지 않는다.

사유 선택지 = `EDUCATION_FEE` · `LECTURER_FEE` · `SHORT_TERM_VEHICLE_LEASE` ·
`OTHER`, 안내 문구 = *"단기 차량 임차 여부는 사업부서 품의서를 확인하여
판단합니다. 단발성 출장을 위해 출장지에서 빌린 차량이면 기간과 관계없이 단기
차량 임차입니다."*

**STEP H.5 — 분모·분자 (가장 중요한 확인)**

```
제외 전            분모 15,000  분자 2,000  달성률 44.44
① 비정책 1,000 제외 분모 14,000  분자 2,000   ← 분모만 감소 (정상)
② 정책 1,000 제외   분모 13,000  분자 1,000   ← 분모·분자 모두 감소 (정상)
되돌린 뒤          분모 14,000  분자 2,000
이력               [EXCLUDED, INCLUDED]
예산과목 건 되돌리기 시도 → status 그대로 EXCLUDED
```

⭐ **분모에서만 빼는 동작은 없었다.** 제외한 거래가 정책 인증기업 거래이면
분자도 같이 줄고, 아니면 분모만 준다 — 둘 다 맞다.

**STEP I — 달성률 손계산**

```
분자 1,000 ÷ 분모 13,000 = 구매비율 7.6923%
7.6923 ÷ 목표 30 × 100  = 25.64
API achievement_rate    = 25.64   ← 일치
```

목표율 미설정 정책 3종은 `achievement_rate=null` · `status=TARGET_RATE_NOT_SET`
로 나온다(0% 로 표시되지 않는다).

**STEP L — 재업로드 · 실패 업로드**

```
파일 A(6,000) 업로드 → batch 1 ACTIVE
파일 B(9,000) 확인 없이 업로드 → 409
파일 B(replace_existing) → batch 2 ACTIVE · batch 1 SUPERSEDED(superseded_by=2)
purchase 원본 행 = 2건 (삭제되지 않음)
분모 = 9,000        ← 15,000 이 아니다 (중복 합산 없음)
KPI 적재 합계 = 15,000  ← 분모와 다른 것이 정상

잘못된 파일 업로드 → ok=false · stored=false · error_rows=1
  배치 상태 [(1, SUPERSEDED), (2, ACTIVE)]  ← 그대로
  purchase 행 2건 그대로 · 분모 9,000 그대로
```

⭐ 실패 업로드가 **기존 ACTIVE 배치를 SUPERSEDED 시키지 않았고**, 부분 저장도
없었다.

## 3. 수동 확인이 필요한 항목

시스템 값은 볼 수 있으나 **시스템 밖 자료**를 사람이 봐야 결정되는 것들이다.

| 항목 | 필요한 자료 | 왜 시스템이 못 하는가 |
|---|---|---|
| 단기 차량 임차 판정 | **사업부서 품의서** | 품의서가 데이터에 없다. 기간·낱말로 대신하면 사람이 확인하지 않은 판정이 실적이 된다 |
| 교육비 · 강사료 판정 | **지출결의서 · 세금계산서 내역** | 고객이 두 자료를 직접 확인한다고 답했고, 그 자료가 시스템에 없다 |
| 고객 지목 2건 확정 | 위 두 자료 + 실제 고객 데이터 | 적요 문구만으로 같은 문구의 다른 거래까지 사라질 수 있다 |
| 구매유형 확정 | 지출결의서 · 세금계산서 | 자동분류를 만들지 않았다 |
| 지출결의서 대조 | 종이 결의서 | 결의번호가 없다. 적요·업체·사업자번호·금액을 맞대어 본다 |

## 5. 발견된 문제

### ① 사업자등록번호를 **인쇄된 형태로 검색하면 0건** (제품 결함 · 수정함)

| 항목 | 내용 |
|---|---|
| 문제 | `119-81-02316` 로 검색 → **0건**. `1198102316` 로 검색 → 17건 |
| 재현 | `GET /reviews?page=1&search=119-81-02316` · `GET /dashboard/unmatched-companies?search=119-81-02316` |
| 원인 | 검색어를 적요용 정규화(공백 제거)만 거쳐 비교했다. 구매의 `business_no` 는 **숫자만** 저장되므로 하이픈이 든 검색어와 절대 겹치지 않는다 |
| 영향 범위 | 검토 화면 검색 · 검토 CSV 내보내기 · 미매칭 기업 검색 |
| 왜 결함인가 | 고객이 확정한 Q5-3 대조 수단이 **사업자등록번호**이고, 지출결의서·세금계산서에는 **하이픈이 있는 형태로 인쇄**된다. 종이에 있는 그대로 옮겨 적으면 0건이 나오고, **0건은 "그런 거래가 없다" 로 읽힌다** |
| 업무규칙 변경 여부 | **없음** — 무엇을 실적에 넣고 빼는지는 그대로다 |
| DB 변경 여부 | **없음** |
| 수정 | `matchers/business_no.py` 에 `business_no_search_key()` 추가(구분자만 제거), 검토 검색과 미매칭 검색에서 사업자번호에 한해 **한 번 더** 비교 |
| 확인 | 수정 후 `119-81-02316` · `1198102316` 둘 다 17건 |

⛔ **정규화가 아니다.** `business_no_search_key` 는 **비교용**이며 값을 저장하거나
기업을 연결하는 데 쓰지 않는다. 자릿수·체크섬도 따지지 않는다(앞 몇 자리만
넣는 검색이 흔하기 때문).

### ② 기업정보의 사업자등록번호 표기 (운영 주의 · 수정하지 않음)

| 항목 | 내용 |
|---|---|
| 문제 | `CompanyRepository` 는 사업자등록번호를 **정규화하지 않고 그대로** 저장한다. 구매는 적재 시 숫자만 남기므로, 기업을 `220-81-62517` 로 등록하면 `2208162517` 인 구매와 **영원히 매칭되지 않는다** |
| 재현 | 하이픈 표기로 기업·인증을 등록한 뒤 업로드 → 매칭 0건 · 분자 0 |
| 영향 범위 | 기업 매칭률 · 정책 구매액(분자) |
| 왜 위험한가 | 오류가 나지 않는다. **조용히 분자가 0** 이 되고, 화면에는 "미매칭" 으로만 보인다 |
| 수정 여부 | **하지 않음.** 저장 형식을 바꾸는 일이라 기존 데이터·스키마에 영향이 있고, 이번 STEP 범위를 넘는다 |
| 대응 | 체크리스트 STEP F 에 확인 항목으로 남기고 별도 STEP 으로 제안 |

### ③ 개선 제안 (고객 요구사항 아님 · 구현하지 않음)

⛔ 아래는 **검수자의 의견**이며 고객이 요청한 적이 없다. 고객 확정사항으로
승격하지 않는다.

- 실적 제외 건수·금액 집계가 있으면 STEP K 를 건별로 세지 않아도 된다.
- 금액을 검색어로 넣을 수 있으면 지출결의서 대조가 빨라질 수 있다.
  (⚠️ 다만 표기·부호 문제로 "못 찾은 것" 을 "없는 것" 으로 오해할 위험이 있다)
- 구매비율(`purchase_amount ÷ total_purchase_amount`)이 응답에 있으면 손계산이
  필요 없다.

## 6. 미확정 사항

검수 중 해당 사례를 만났으나 **어느 것도 결정하지 않았다.**

| 항목 | 검수에서 만난 사례 | 처리 |
|---|---|---|
| **W-1-2** 인증 유효기간 판정 기준일 | 기준일 미설정이면 달성률 조회가 503 | 지급일을 **시험용으로 주입**했을 뿐이다. 확정하지 않음 |
| **Q5-8** 0원·음수 행 | 0원 1행 · 음수 1행이 `NON_POSITIVE_AMOUNT` 로 미적재 | **미적재**로만 기록. "실적 제외" 라고 쓰지 않음 |
| **Q5-9** 예산과목 공란 | 음수 행의 예산과목이 공란 | 공란을 제외 조건으로 쓰지 않음 |
| **W-11 ~ W-15** | 해당 사례 없음 | 그대로 |
| 구매유형 자동분류 | PENDING 22건 | 자동 확정하지 않음. 담당자 몫 |

## 7. 최종 판정

```
[x] 운영 검수 가능
[ ] 일부 보완 필요
[ ] 고객 확인 후 재검수 필요
```

**단, 두 가지 전제가 있다.**

1. 운영 환경에 **기간 판정 기준일이 설정되어 있어야** STEP E~J 를 수행할 수
   있다(W-1-2 확정 전까지는 설정 자체가 임시값이다).
2. 기업정보를 등록할 때 사업자등록번호 표기를 확인해야 한다(§5-②).

실제 고객 데이터로는 아직 검수하지 않았다. 이 문서는 **절차가 동작한다**는
기록이지, **고객 실적이 맞다**는 기록이 아니다.
