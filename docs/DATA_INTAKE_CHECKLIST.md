# 1. 목적

실제 데이터(고객 구매데이터 · 외부 기업/인증정보)를 받았을 때
**개발자가 바로 확인할 수 있는 체크리스트**와,
**"어떤 데이터가 어느 DB 필드로 들어가는가"** 를 정리한다.

# 2. 정책별 데이터 흐름

> ⚠️ **필요한 필드는 실제 API 응답을 확인하기 전까지 확정하지 않는다.**
> 아래 "필요한 필드"는 **계산에 반드시 있어야 하는 항목**(우리 쪽 요구사항)이며,
> **API 가 실제로 제공하는지는 미확인**이다.

| 정책 | 외부 데이터 | 필요한 필드 (우리 요구) | 현재 DB 필드 | Collector 위치 (예정) | 인증키 |
|---|---|---|---|---|---|
| **중소기업** | 중소벤처24 (중소기업기술정보진흥원) | 사업자번호 · 인증 유효기간(시작/종료) · 확인서번호 | `certification.company_id`(사업자번호로 조회) · `valid_from` · `valid_to` · `certificate_number` | `collectors/sme/` | **필요(심사)** |
| **여성기업** | SMPP 인증서 API (한국중소벤처기업유통원) | 〃 | 〃 | `collectors/smpp/` | 필요 |
| **장애인기업** | SMPP 인증서 API (동일 API) | 〃 | 〃 | `collectors/smpp/` (여성기업과 **공용**) | 필요 |
| **창업기업** | 창업진흥원 창업기업확인서 | 〃 | 〃 | `collectors/startup/` | 필요 |
| **녹색제품** | 별도 조사 필요 | **미확정** (판정 단위 미결) | **미확정** | **보류** | — |

## 2.1 공통 필수 요구사항

어떤 API 든 아래 두 가지가 없으면 **계산이 불가능**하다.

| # | 필드 | 이유 |
|---|---|---|
| 1 | **사업자등록번호** | 유일한 결합 키. 없으면 기업과 연결 불가 |
| 2 | **인증 유효기간(시작일·종료일)** | `valid_from ≤ 판정기준일 ≤ valid_to` 판정에 필수 |

> **선택 필드**: 확인서번호(`certificate_number`), 발급기관(`issuing_agency`) — 증빙·추적용.
> 없어도 계산은 가능하다.

## 2.2 기업정보(Company) 요구사항

| 필드 | DB | 필수 여부 | 비고 |
|---|---|---|---|
| 사업자등록번호 | `company.business_no` | **필수** | Unique |
| 기업명 | `company.company_name` | **필수** | |
| 대표자명 | `company.representative_name` | 현재 **필수** | ⚠️ API 미제공 가능 → nullable 전환 승인됨(미구현) |

> ⚠️ **API 가 대표자명을 제공하지 않으면 현재 코드로는 Company 를 만들 수 없다.**
> nullable 전환은 승인되었으나 아직 구현되지 않았다. **응답 확인 시 최우선 점검 항목**이다.

# 3. 구매데이터 체크리스트

## 3.1 필수 항목

| # | 확인 항목 | 판정 |
|---|---|---|
| 1 | **사업자등록번호** 컬럼 존재 | 없으면 **즉시 중단** |
| 2 | **구매금액** 컬럼 존재 | 없으면 **즉시 중단** |
| 3 | **계약일** 컬럼 존재 | 없으면 창업기업 계산 불가 |
| 4 | **지급일** 컬럼 존재 | 없으면 나머지 4개 정책 계산 불가 |
| 5 | 업체명 컬럼 존재 | 없으면 `(미상)` 대체 + 경고 |
| 6 | 정책 판정용 기타 날짜 존재 여부 | 향후 정책 확장 대비 |

# 5. 인증정보 체크리스트

| # | 확인 항목 | 비고 |
|---|---|---|
| 1 | **사업자등록번호** 제공 | **없으면 연결 불가** |
| 2 | **정책 종류** 식별 가능 | `policy_code` 매핑 필요 |
| 3 | **인증 시작일(`valid_from`)** | **없으면 판정 불가** |
| 4 | **인증 종료일(`valid_to`)** | **없으면 판정 불가** |
| 5 | 인증 상태(유효/취소/정지) | 현재 DB 필드 없음 — 취소 인증 처리 방침 필요 |
| 6 | 확인서 번호 | 선택 (`certificate_number`) |
| 7 | 발급기관 | 선택 (`issuing_agency`) |
| 8 | 한 기업의 **복수 인증** 제공 방식 | 여러 건이면 하나라도 유효 시 인정 |
| 9 | **저장·캐싱 허용 여부(약관)** | ⚠️ 제한 시 설계 변경 필요 |

> **5번 주의**: 현재 모델에는 인증 상태 필드가 없다. API 가 "취소된 인증"을 함께
> 내려주면 **유효한 인증으로 잘못 저장될 수 있다.** 응답 확인 시 점검 필요.

---

# 6. 확인 순서 (권장)

```
[1] 필수 컬럼/필드 존재 확인      → 없으면 즉시 재요청
[2] 사업자번호 형식 실태 조사     → 정규화 규칙·매칭률 예측
[3] 날짜·금액 형식 조사           → 파싱 규칙 확정
[4] 품질 리포트 작성              → 결측·중복·음수 건수
[5] 컬럼 매핑표 확정
[6] 정책별 계산 가능 여부 판정
```

> **2번이 가장 중요하다.** 사업자번호가 어긋나면 나머지가 모두 무의미하다.

---

# 7. 요약

- 계산에 **반드시 필요한 것은 사업자번호 + 인증 유효기간** 두 가지다.
- 현재 시스템이 **저장하지 못하는 데이터**: 9자리 사업자번호, 음수·0 금액.
- **대표자명 미제공**과 **인증 상태 필드 부재**는 응답 확인 시 최우선 점검 항목이다.
- API 응답 필드는 **실제 확인 전까지 확정하지 않는다.**
