# 후속 질문 (2026-08-14 회신에 이어서)

## Q1-1. `결의일자`가 대금 지급 완료일과 같은 날짜입니까? 🔴

> **"구매실적 산정 기준일은 `결의일자`" 로 확인해 주셨습니다.
> 그러면 `결의일자`가 실제로 **대금이 지급 완료된 날**과 같은 것입니까,
> 아니면 지급 완료일과는 다르지만 **실적 산정에는 `결의일자`를 쓰는** 것입니까?**

**왜 필요한가**: 시스템 내부 필드가 "대금 지급일" 이라는 의미로 정의되어 있습니다.
두 날짜가 다른 개념이라면 필드 정의와 문서를 바로잡아야, 나중에 지급일이 별도로
필요해졌을 때 값이 섞이지 않습니다. **계산 결과 자체는 어느 쪽이든 동일합니다.**

## Q1-2. 결의일자 기준입니까, 계약일자 기준입니까? ✅ **회신 완료**

> **앞서 "구매실적 산정 기준일은 `결의일자`" 로 확인해 주셨는데,
> 이후 "창업기업을 제외하고는 계약일자 컬럼으로 실적을 확인하면 된다" 는
> 말씀도 전달받았습니다. 두 내용이 서로 반대로 읽힙니다.
> 어느 쪽이 맞습니까?**

| | 일반 정책 | 창업기업 |
|---|---|---|
| **A안** (앞선 확정) | 결의일자 | 결의일자 + 계약일자 |
| **B안** (이후 발언) | **계약일자** | 계약일자가 아닌 다른 기준 |

**왜 필요한가**: 기준일이 바뀌면 **모든 정책의 연도별 실적이 통째로 달라집니다.**
또한 현재 제공된 매입매출장에는 **계약일자 컬럼이 없어**, B안이라면 어느 파일의
계약일자를 쓰는지도 함께 확인해야 합니다.

### ✅ 회신 (2026-08-14)

> 구매실적은 **결의일자** 기준. 다만 **창업기업**은 결의일자와 계약일자가
> 기업 인증 유효기간에 해당할 경우 **모두** 실적으로 인정한다.

→ **A안**이 맞습니다. 일반 정책의 기준은 결의일자이며, 창업기업만 두 날짜를
**OR** 로 판정합니다. 코드에 반영 완료(`DECISIONS.md` §0.6.2).

## Q4-1. 음수 거래와 원래 거래를 무엇으로 짝지어야 합니까? ✅ **회신 완료**

> **"동일 거래의 양수와 상계하여 0원 처리" 로 확인해 주셨습니다.
> 그러면 어떤 거래가 **같은 거래**인지 판단할 때 어느 값을 비교해야 합니까?**

**저희가 확인한 문제 — 샘플에서는 짝지을 수 없습니다.** (음수 125건 전수 조사)

| 후보 컬럼 | 음수 125건 중 채워진 건수 | 판정 |
|---|---|---|
| `기표번호` | **0건** | ❌ 전부 비어 있음 |
| `결의번호` | **0건** | ❌ 전부 비어 있음 |
| `LN_SQ` | **0건** | ❌ 전부 비어 있음 |
| `GRP_NB` | **0건** | ❌ 전부 비어 있음 |
| `사업자번호` | 125건 | ⚠️ 거래처 단위 — 같은 거래처의 다른 거래와 구분 불가 |
| `적요` | 채워짐 | ⚠️ 자유 텍스트 — 동일 문구가 여러 거래에 반복 |

**금액으로도 짝지을 수 없습니다**: 같은 금액이 중복 존재합니다
(`−132,000` 2건, `−200,000` 2건 등). 어느 거래의 취소인지 결정할 수 없습니다.
또한 음수 **24건(19.2%)** 은 같은 사업자에 **금액이 같은 양수 거래가 아예 없습니다.**

**여쭙고 싶은 것**

1. 실제 운영데이터에서는 `결의번호`·`기표번호`가 **음수 행에도 채워집니까?**
2. 채워지지 않는다면, 원거래를 가리키는 **별도의 번호**가 있습니까?
3. 위 24건처럼 대응하는 양수가 없는 음수는 **어떻게 처리해야 합니까?**
4. 상계 대상을 찾는 기간 범위가 있습니까? (예: 같은 연도 안에서만)

### ✅ 회신 (2026-08-14)

> 음수 거래 이전에 **기업명 · 사업자번호 · 금액**이 똑같은 양수 금액이 있으면
> 동일 거래로 판단한다.

→ 판별 후보는 위 표의 컬럼이 아니라 **기업명 + 사업자등록번호 + 절대금액** 입니다
(2026-08-19 정정: **날짜는 조건이 아님** — "이전 거래" 조건 철회). 로직 구현 완료
(`core.offsetting`).

> 🔴 **2026-08-20 재개봉.** 추가 회신에서 담당자가 상계 판단 시 **적요 · 사업자등록번호 ·
> 금액 · 예산과목 · 거래처(기업)** 5가지를 **종합적으로** 확인한다는 사실이 확인되어,
> 위 3가지만으로 자동 상계하는 것은 **최종 규칙으로 확정하지 않습니다.** → Q4-2 · Q4-3

> 🔴 **다만 계산에 연결하지 못했습니다.** 현재 시스템이 음수 금액의 저장 자체를
> 거부하고 있어, 상계 대상 데이터가 DB 에 들어오지 않습니다. 저장 제약 해제는
> 별도 결정 사항입니다.
>
> 또한 위 4번(**대응 양수가 없는 음수 24건**)과 **상계 대상 기간 범위**는
> 여전히 확인이 필요합니다.

## Q4-2. 후보 양수가 여러 건일 때 어느 거래를 상계합니까? ✅ **회신 완료 (2026-08-20 2차)** → Q4-4 로 좁혀짐

> **동일 기업 · 동일 사업자등록번호 · 동일 금액의 양수 거래가 여러 건 있고, 이에
> 대응하는 (−)세금계산서가 있을 때, 적요와 예산과목이 서로 다른 거래가 여러 개라면
> 어떤 거래를 상계 대상으로 선택하십니까?**

예시:

```text
양수  A기업 / 100만원 / "에스프레소 원두(디카페인)"        / 예산과목 A
양수  A기업 / 100만원 / "에스프레소 원두(디카페인) - 4월 분" / 예산과목 B
음수  A기업 / −100만원
```

**저희가 실측한 규모** (2026년 매입 2,292행 · 음수 129건):

| 구분 | 건수 |
|---|---|
| 후보가 1건뿐이라 자명한 상계 | 48쌍 |
| 🔴 **후보가 여러 건이라 선택이 필요** | **67그룹 · 음수 78건** |
| 대응 양수가 아예 없는 음수 | 3건 (사업비 잔액 반환금 등) |

> 어느 양수를 고르든 **상계 건수와 달성률은 같습니다.** 달라지는 것은 **남는 거래의
> 적요 · 예산과목**이며, 이후 물품/용역/공사 분류에 영향을 줄 수 있습니다.

## Q4-4. 발행일자 차이가 **똑같이 가까운** 후보가 2건 이상일 때는? ✅ **회신 완료 (3차)**

차이가 다르면 문제가 없습니다.

```text
양수 A : 1월 10일   (10일 차이)
양수 B : 1월 15일   ( 5일 차이)   ← B 선택. 명확합니다.
음수   : 1월 20일
```

문제는 **최소 차이가 같은 후보가 둘 이상**일 때입니다.

```text
양수 A : 1월 10일   (10일 차이)
양수 B : 1월 15일   ( 5일 차이)  ┐
음수   : 1월 20일               ├ B 와 C 중 어느 것을 상계해야 합니까?
양수 C : 1월 25일   ( 5일 차이)  ┘
```

**2026년 데이터에서 실제로 몇 건인지 세어 보았습니다 — 54건**입니다.

| 동률의 형태 | 건수 |
|---|---|
| **후보들의 발행일자가 완전히 같음** (차이 0일) | **50건** |
| 위 예시처럼 **이전/이후로 갈리며 차이가 같음** | **0건** |
| 같은 방향에서 차이가 같음 | 4건 |

즉 실제로는 대부분 **같은 날 발행된 (+) 가 여러 건**인 경우입니다.

```text
−16,900  엘지전자(주)  발행 2026-01-05
  ↳ 후보 (+) 4건이 전부 2026-01-05 발행  → 어느 것을 상계해야 합니까?
```

적요로 좁혀 보았지만 끝까지 가려지지 않았습니다.

| 적요로 좁힌 결과 | 건수 |
|---|---|
| 하나로 좁혀짐 | 38건 |
| 적요가 같은 후보가 **하나도 없음** | 7건 |
| **여전히 2건 이상** | 9건 |

> 어느 (+) 를 고르든 **상계 건수와 달성률은 같습니다.** 달라지는 것은 **남는 거래의
> 적요·예산과목**이며, 이후 물품/용역/공사 분류에 영향을 줄 수 있습니다.
>
> 실무에서 이런 경우 **어떻게 정하시는지** 알려주시면 그대로 반영하겠습니다.
> (예: 지출결의서를 열어 확인한다 / 예산과목을 본다 / 어느 것을 골라도 무방하다)

> ⛔ **저희가 임의로 정하지 않습니다.** 파일 순서 · 적요 유사도 · 먼저 발생한 거래
> 같은 기준을 임의로 넣지 않고, 답변을 받은 뒤 반영하겠습니다.

## Q4-5. 적요가 서로 다를 때도 상계합니까? ✅ **회신 완료 (3차)**

동일 기업 · 동일 사업자등록번호 · 동일 금액이지만 **적요가 다른** 경우,
**예산과목 · 발행일자 등 다른 조건을 종합하여 상계**하는 것이 맞습니까?

"적요가 달라서 매칭하지 못한 사례는 없었다" 고 답해 주셨는데, 저희 실측에서는
**후보가 하나뿐인 자명한 경우에도 적요가 다른 쌍이 7 / 101** 있었습니다.

| 규칙 | 상계 쌍 | 담당자께서 표시하신 것 대비 |
|---|---|---|
| 적요를 **필수 조건으로 쓰지 않음** | 126쌍 | 놓침 0 |
| 적요 **완전일치를 필수**로 함 | 115쌍 | **22행 놓침** |

→ 저희는 **적요가 다르다는 이유만으로 자동 제외하지 않고**, 적요를 후보를 좁히는
참고 정보로만 쓰려 합니다. 맞습니까?

| 상황 | 시스템 처리 |
|---|---|
| 후보 0건 | 짝 없음으로 보고 (상계하지 않음) |

| 후보 2건 이상 | 🟡 **담당자 확인 대상** — 후보의 발행일자·적요·예산과목을 나란히 제시 |

72쌍 중 5쌍이 담당자 처리와 달랐고(한 건은 4일 대 5일 차이로 뒤집혔습니다), 말씀해
주신 업무 방식과도 맞지 않았습니다.

**요청하신 5건**은 `DECISIONS.md` §0.6.3.4 에 기업명·사업자등록번호·금액·발행일자·
적요까지 그대로 정리해 두었습니다. 다만 새 규칙에서는 **5건 모두 후보가 2건 이상**
이므로 자동으로 담당자 확인 대상이 됩니다.
