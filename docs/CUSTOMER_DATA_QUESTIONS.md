# 후속 질문 (2026-08-14 회신에 이어서)

## Q1-1. `결의일자`가 대금 지급 완료일과 같은 날짜입니까? 🔴

> **"구매실적 산정 기준일은 `결의일자`" 로 확인해 주셨습니다.
> 그러면 `결의일자`가 실제로 **대금이 지급 완료된 날**과 같은 것입니까,
> 아니면 지급 완료일과는 다르지만 **실적 산정에는 `결의일자`를 쓰는** 것입니까?**

**왜 필요한가**: 시스템 내부 필드가 "대금 지급일" 이라는 의미로 정의되어 있습니다.
두 날짜가 다른 개념이라면 필드 정의와 문서를 바로잡아야, 나중에 지급일이 별도로
필요해졌을 때 값이 섞이지 않습니다. **계산 결과 자체는 어느 쪽이든 동일합니다.**

## Q1-2. 결의일자 기준입니까, 계약일자 기준입니까? ✅ **회신 완료**

> **앞서 "구매실적 산정 기준일은 `결의일자`" 로 확인해 주셨는데,
> 이후 "창업기업을 제외하고는 계약일자 컬럼으로 실적을 확인하면 된다" 는
> 말씀도 전달받았습니다. 두 내용이 서로 반대로 읽힙니다.
> 어느 쪽이 맞습니까?**

| | 일반 정책 | 창업기업 |
|---|---|---|
| **A안** (앞선 확정) | 결의일자 | 결의일자 + 계약일자 |
| **B안** (이후 발언) | **계약일자** | 계약일자가 아닌 다른 기준 |

**왜 필요한가**: 기준일이 바뀌면 **모든 정책의 연도별 실적이 통째로 달라집니다.**
또한 현재 제공된 매입매출장에는 **계약일자 컬럼이 없어**, B안이라면 어느 파일의
계약일자를 쓰는지도 함께 확인해야 합니다.

### ✅ 회신 (2026-08-14)

> 구매실적은 **결의일자** 기준. 다만 **창업기업**은 결의일자와 계약일자가
> 기업 인증 유효기간에 해당할 경우 **모두** 실적으로 인정한다.

→ **A안**이 맞습니다. 일반 정책의 기준은 결의일자이며, 창업기업만 두 날짜를
**OR** 로 판정합니다. 코드에 반영 완료(`DECISIONS.md` §0.6.2).

## Q4-1. 음수 거래와 원래 거래를 무엇으로 짝지어야 합니까? ✅ **회신 완료**

> **"동일 거래의 양수와 상계하여 0원 처리" 로 확인해 주셨습니다.
> 그러면 어떤 거래가 **같은 거래**인지 판단할 때 어느 값을 비교해야 합니까?**

**저희가 확인한 문제 — 샘플에서는 짝지을 수 없습니다.** (음수 125건 전수 조사)

| 후보 컬럼 | 음수 125건 중 채워진 건수 | 판정 |
|---|---|---|
| `기표번호` | **0건** | ❌ 전부 비어 있음 |
| `결의번호` | **0건** | ❌ 전부 비어 있음 |
| `LN_SQ` | **0건** | ❌ 전부 비어 있음 |
| `GRP_NB` | **0건** | ❌ 전부 비어 있음 |
| `사업자번호` | 125건 | ⚠️ 거래처 단위 — 같은 거래처의 다른 거래와 구분 불가 |
| `적요` | 채워짐 | ⚠️ 자유 텍스트 — 동일 문구가 여러 거래에 반복 |

**금액으로도 짝지을 수 없습니다**: 같은 금액이 중복 존재합니다
(`−132,000` 2건, `−200,000` 2건 등). 어느 거래의 취소인지 결정할 수 없습니다.
또한 음수 **24건(19.2%)** 은 같은 사업자에 **금액이 같은 양수 거래가 아예 없습니다.**

**여쭙고 싶은 것**

1. 실제 운영데이터에서는 `결의번호`·`기표번호`가 **음수 행에도 채워집니까?**
2. 채워지지 않는다면, 원거래를 가리키는 **별도의 번호**가 있습니까?
3. 위 24건처럼 대응하는 양수가 없는 음수는 **어떻게 처리해야 합니까?**
4. 상계 대상을 찾는 기간 범위가 있습니까? (예: 같은 연도 안에서만)

### ✅ 회신 (2026-08-14)

> 음수 거래 이전에 **기업명 · 사업자번호 · 금액**이 똑같은 양수 금액이 있으면
> 동일 거래로 판단한다.

→ 판별 후보는 위 표의 컬럼이 아니라 **기업명 + 사업자등록번호 + 절대금액** 입니다
(2026-08-19 정정: **날짜는 조건이 아님** — "이전 거래" 조건 철회). 로직 구현 완료
(`core.offsetting`).

> 🔴 **2026-08-20 재개봉.** 추가 회신에서 담당자가 상계 판단 시 **적요 · 사업자등록번호 ·
> 금액 · 예산과목 · 거래처(기업)** 5가지를 **종합적으로** 확인한다는 사실이 확인되어,
> 위 3가지만으로 자동 상계하는 것은 **최종 규칙으로 확정하지 않습니다.** → Q4-2 · Q4-3

> 🔴 **다만 계산에 연결하지 못했습니다.** 현재 시스템이 음수 금액의 저장 자체를
> 거부하고 있어, 상계 대상 데이터가 DB 에 들어오지 않습니다. 저장 제약 해제는
> 별도 결정 사항입니다.
>
> 또한 위 4번(**대응 양수가 없는 음수 24건**)과 **상계 대상 기간 범위**는
> 여전히 확인이 필요합니다.

> **동일 기업 · 동일 사업자등록번호 · 동일 금액의 양수 거래가 여러 건 있고, 이에
> 대응하는 (−)세금계산서가 있을 때, 적요와 예산과목이 서로 다른 거래가 여러 개라면
> 어떤 거래를 상계 대상으로 선택하십니까?**

예시:

```text
양수  A기업 / 100만원 / "에스프레소 원두(디카페인)"        / 예산과목 A
양수  A기업 / 100만원 / "에스프레소 원두(디카페인) - 4월 분" / 예산과목 B
음수  A기업 / −100만원
```

| 구분 | 건수 |
|---|---|
| 후보가 1건뿐이라 자명한 상계 | 48쌍 |
| 🔴 **후보가 여러 건이라 선택이 필요** | **67그룹 · 음수 78건** |
| 대응 양수가 아예 없는 음수 | 3건 (사업비 잔액 반환금 등) |

> 어느 양수를 고르든 **상계 건수와 달성률은 같습니다.** 달라지는 것은 **남는 거래의
> 적요 · 예산과목**이며, 이후 물품/용역/공사 분류에 영향을 줄 수 있습니다.

## Q4-4. 발행일자 차이가 **똑같이 가까운** 후보가 2건 이상일 때는? ✅ **회신 완료 (3차)**

차이가 다르면 문제가 없습니다.

```text
양수 A : 1월 10일   (10일 차이)
양수 B : 1월 15일   ( 5일 차이)   ← B 선택. 명확합니다.
음수   : 1월 20일
```

문제는 **최소 차이가 같은 후보가 둘 이상**일 때입니다.

```text
양수 A : 1월 10일   (10일 차이)
양수 B : 1월 15일   ( 5일 차이)  ┐
음수   : 1월 20일               ├ B 와 C 중 어느 것을 상계해야 합니까?
양수 C : 1월 25일   ( 5일 차이)  ┘
```

**2026년 데이터에서 실제로 몇 건인지 세어 보았습니다 — 54건**입니다.

| 동률의 형태 | 건수 |
|---|---|
| **후보들의 발행일자가 완전히 같음** (차이 0일) | **50건** |
| 위 예시처럼 **이전/이후로 갈리며 차이가 같음** | **0건** |
| 같은 방향에서 차이가 같음 | 4건 |

즉 실제로는 대부분 **같은 날 발행된 (+) 가 여러 건**인 경우입니다.

```text
−16,900  엘지전자(주)  발행 2026-01-05
  ↳ 후보 (+) 4건이 전부 2026-01-05 발행  → 어느 것을 상계해야 합니까?
```

적요로 좁혀 보았지만 끝까지 가려지지 않았습니다.

| 적요로 좁힌 결과 | 건수 |
|---|---|
| 하나로 좁혀짐 | 38건 |
| 적요가 같은 후보가 **하나도 없음** | 7건 |
| **여전히 2건 이상** | 9건 |

> 어느 (+) 를 고르든 **상계 건수와 달성률은 같습니다.** 달라지는 것은 **남는 거래의
> 적요·예산과목**이며, 이후 물품/용역/공사 분류에 영향을 줄 수 있습니다.
>
> 실무에서 이런 경우 **어떻게 정하시는지** 알려주시면 그대로 반영하겠습니다.
> (예: 지출결의서를 열어 확인한다 / 예산과목을 본다 / 어느 것을 골라도 무방하다)

> ⛔ **저희가 임의로 정하지 않습니다.** 파일 순서 · 적요 유사도 · 먼저 발생한 거래
> 같은 기준을 임의로 넣지 않고, 답변을 받은 뒤 반영하겠습니다.

## Q4-5. 적요가 서로 다를 때도 상계합니까? ✅ **회신 완료 (3차)**

동일 기업 · 동일 사업자등록번호 · 동일 금액이지만 **적요가 다른** 경우,
**예산과목 · 발행일자 등 다른 조건을 종합하여 상계**하는 것이 맞습니까?

"적요가 달라서 매칭하지 못한 사례는 없었다" 고 답해 주셨는데, 저희 실측에서는
**후보가 하나뿐인 자명한 경우에도 적요가 다른 쌍이 7 / 101** 있었습니다.

| 규칙 | 상계 쌍 | 담당자께서 표시하신 것 대비 |
|---|---|---|
| 적요를 **필수 조건으로 쓰지 않음** | 126쌍 | 놓침 0 |
| 적요 **완전일치를 필수**로 함 | 115쌍 | **22행 놓침** |

→ 저희는 **적요가 다르다는 이유만으로 자동 제외하지 않고**, 적요를 후보를 좁히는
참고 정보로만 쓰려 합니다. 맞습니까?

주신 업무 방식과도 맞지 않았습니다.

적요까지 그대로 정리해 두었습니다. 다만 새 규칙에서는 **5건 모두 후보가 2건 이상**

# 인증 API 연동 관련 질문 (2026-08-28 · STEP 54)

> 인증서 조회 API 4종(창업기업·여성기업·장애인기업·직접생산확인)의 연동을
> 마무리하려면 아래 답변이 필요합니다. ⛔ **어느 것도 개발 측에서 임의로 정하지
> 않았습니다.**

## Q-A. 인증 유효기간을 어떤 날짜로 판정합니까 (W-1-2)

앞서 *"결의일자를 기준으로 연도 귀속·실적을 산정한다"* 고 확정해 주셨습니다.
여기서 **"실적 산정" 이 인증 유효기간 판정까지 포함**하는지 확인이 필요합니다.

구매 한 건이 인증기업 실적으로 인정되려면, 아래 날짜가 그 기업의 인증
유효기간(`시작일 ~ 만료일`) 안에 들어야 합니다. **어느 날짜를 볼지**를 묻는
질문입니다.

| | 중소기업 | 여성기업 | 장애인기업 | 창업기업 |
|---|---|---|---|---|
| **① 현행 유지** | 대금 지급일 | 대금 지급일 | 대금 지급일 | 결의일자 **또는** 계약일자 |
| **② 결의일자 기준** | 결의일자 | 결의일자 | 결의일자 | 〃 (변경 없음) |

⚠️ **②를 택하시면 이미 산출한 달성률 숫자가 달라집니다.**

## Q-B. 인증서 조회 API 의 기준일자는 무엇으로 합니까 (W-11)

조회 API 는 `기준일자` 를 **요청 파라미터**로 요구합니다. 공식 설명은
*"유효확인서를 확인할 기준일자"* 입니다.

⚠️ **Q-A 와 다른 질문입니다.** Q-A 는 "계산할 때 어느 날짜를 보는가",
Q-B 는 "조회할 때 어느 시점의 확인서를 달라고 할 것인가" 입니다. Q-A 에 ②로
답하시더라도 Q-B 가 자동으로 정해지지는 않습니다.

| 안 | 내용 |
|---|---|
| ① | 구매 건별 판정 기준일과 **같은 날짜**로 조회 (구매 건마다 조회) |
| ② | **조회하는 날(오늘)** 기준으로 조회 |
| ③ | **회계연도 말일** 등 고정일 기준으로 조회 |
| ④ | 그 밖의 기준 (지정해 주십시오) |

## Q-C. 직접생산확인증명을 어떻게 쓸 것입니까 (W-12 · W-13)

직접생산확인증명은 다른 확인서와 **성격이 다릅니다.** 여성·장애인·창업은
"이 업체가 해당 기업인가" 이지만, 직접생산은 **물품(세부품명번호) 단위**로
발급됩니다. 한 업체가 품목마다 확인서를 갖습니다.

1. **세부품명번호를 구매실적과 어떻게 연결**합니까? 현재 받고 있는 구매 데이터에는
   품목번호 컬럼이 없습니다.
2. 직접생산확인을 **어느 정책의 실적**으로 봅니까? 현재 관리 중인 5개 정책
   (중소·여성·장애인·창업·녹색) 어느 것에도 대응시키지 않았습니다.

## Q-D. 시험용 사업자등록번호 1건 (W-14)

각 확인서를 **실제로 보유한 업체**의 사업자등록번호가 있으면 정상 응답 구조를
검증할 수 있습니다. 지금까지 받아본 응답은 "해당 확인서 없음" 뿐이라, 정상
응답이 실제로 어떤 모양인지 확인하지 못했습니다.

한 업체가 여러 확인서를 갖고 있다면 **1건으로 4종을 한 번에** 검증할 수 있습니다.

⚠️ 이 번호는 저장소·문서·로그 어디에도 기록하지 않고, 담당자 PC 의 설정
파일에서만 읽습니다.

## Q-E. 결의일자가 비어 있는 구매 건을 어떻게 처리합니까 (W-15)

구매실적은 **결의일자** 기준으로 연도를 나눕니다(Q1-2 회신). 그런데 시스템에
이미 적재된 구매 중 **결의일자 값이 비어 있는 건**이 있을 수 있습니다. 어느
해의 실적인지 알 수 없어 **연도별 집계에서 빠집니다.**

⚠️ **앞으로 올려 주실 파일 이야기가 아닙니다.** 표준 업로드 양식에서
`결의일자` 는 필수 항목이라, 값이 비어 있으면 그 파일은 저장되지 않고
어디가 비었는지 알려 드립니다. 이 질문은 **표준 양식을 쓰기 전에 이미
들어와 있는 옛 데이터**를 어떻게 할지에 대한 것입니다.

**지금 확인하실 수 있는 것**

대시보드 「정책별 달성률」 아래에 해당 건수·금액이 표시되며, 목록을 펼쳐
행을 직접 보시거나 CSV 로 내려받으실 수 있습니다.

**여쭙는 것**

| 안 | 내용 | 달성률에 미치는 영향 |
|---|---|---|
| ① | **지금처럼 둔다** — 연도별 집계에서 빠지고, 몇 건인지만 화면에 알린다 | 없음(현행) |
| ② | 담당자가 **결의일자를 직접 입력**할 수 있게 한다 | 입력한 해의 실적으로 잡힌다 |
| ③ | 결의일자가 없는 건은 **다른 날짜로 연도를 나눈다** | 그 해의 분모·분자가 커진다 |
| ④ | 그 밖의 방법 (지정해 주십시오) | — |

③을 택하실 경우 **어느 날짜인지**(계약일자 · 지급일 · 신고기준일) 함께
지정해 주셔야 합니다.

⛔ 저희가 임의로 고르지 않았습니다. 값이 없는 결의일자를 다른 날짜로
대체하는 것은 앞서 명시적으로 금지된 사항이라, 지시 없이는 바꾸지 않습니다.

⛔ 이 건들을 "오류"·"무효"·"실적 불인정" 으로 분류하지 않았습니다.
**결의일자가 입력되지 않았다**는 사실만 표시하고 있습니다.

**왜 필요한가**: 결정 전까지는 이 건들이 어느 해 실적인지 정할 수 없어
연도별 달성률에 반영할 수 없습니다. 건수가 많다면 달성률이 실제보다 낮게
보일 수 있습니다.

## QT-1 (원 Q1). 공사와 용역이 함께 적힌 적요 ✅ **회신 완료**

**질문**: `○○조성공사 공사 및 용역 준공금` 처럼 공사와 용역이 함께 적힌 적요는
어떻게 판정하십니까?

**고객 답변**

> 적요에 '○○조성공사 공사 및 용역 준공금' 이런식으로 공사와 용역이 같이
> 작성되어 있으면 그때 지출결의서를 열어 용역건인지 공사건인지 하나하나
> 체크하고 있어.

**확정된 업무규칙**

- 공사와 용역이 **함께** 표현된 복합 적요는 **지출결의서를 확인해 건별로
  판정**한다.
- `용역 준공금` 이라는 표현이 있다고 해서 자동으로 용역으로 확정하지 않는다.

**예외 / 주의사항**

- ⛔ 이것을 **"공사 낱말이 있으면 공사"** 라는 규칙으로 만들지 않는다. 고객
  답변은 정반대다 — 두 낱말이 함께 있으면 **적요만으로는 못 정한다**는 뜻이다.
- `○○용역 준공금` (공사 표현 없음)은 용역으로 볼 수 있는 일반적인 사례다.

**시스템 반영**: ⛔ 자동확정 불가. 복합 적요는 **담당자 확인 대상으로 표시**하는
방향만 가능하다.

## QT-2 (원 Q2). 기념품 ✅ **회신 완료**

**질문**: 기념품은 물품입니까?

**고객 답변**: 기본은 물품. 다만 아래는 **용역**으로 처리했다.

| 실제 사례 | 유형 |
|---|---|
| 환경보건 기념품 **KC인증 비용** | 용역 |
| ENVEX2025 참가기업 설문조사 기념품 **발송 지출** | 용역 |

**확정된 업무규칙**

| 거래 성격 | 유형 |
|---|---|
| 기념품 **자체 구매** | 물품 |
| 기념품 **안전성 인증 비용** | 용역 |
| 기념품 **발송 비용** | 용역 |

**예외 / 주의사항**

- ⛔ `기념품` 이라는 낱말이 있다는 이유만으로 물품으로 확정하지 않는다.
- ⛔ 위 사례를 근거로 `인증` · `발송` 같은 **새 세부 키워드 규칙을 만들지
  않는다.** 확인된 사례가 셋뿐이며, 고객이 규칙으로 제시한 것이 아니다.

**시스템 반영**: 참고 사례로만 기록.

## QT-3 (원 Q3). 소프트웨어 라이선스 ✅ **회신 완료**

**질문**: Adobe · CAD · DreamPlus 등 소프트웨어 라이선스 구매는 어느
유형입니까?

**고객 답변**

> 소프트웨어 라이선스의 구매건들은 물품으로 지정할 거긴 해.

**확정된 업무규칙**: 소프트웨어 라이선스 **구매**는 **물품**.

**예외 / 주의사항**: 예산과목이 `각종수수료` 로 잡힌 건도 있다(QT-8). 즉
예산과목이 아니라 **거래 성격**이 기준이다.

**시스템 반영**: 검토 후보 생성에 활용 가능. ⛔ 확정값으로 미리 채우지 않는다.

## QT-4 (원 Q4). `설치` 가 들어간 거래 ✅ **회신 완료**

**질문**: 적요에 `설치` 가 들어간 거래는 어떻게 판정하십니까?

**고객 답변**: 같은 낱말이 **세 유형 모두**에 나온다.

## QT-5 · QT-6 (원 Q5·Q6). 거래처 동일성 ✅ **회신 완료**

**질문**: 거래처명 표기가 다른 건을 같은 업체의 이력으로 보아도 됩니까?

**고객 답변**: 사업자등록번호가 같으면 같은 업체다.

**확정된 업무규칙**

- **식별키는 사업자등록번호.** 거래처명이 달라도 사업자등록번호가 같으면 같은
  업체의 거래 이력으로 본다.

  예: `SK브로드밴드주식회사` · `SK브로드밴드(주)` · `에스케이브로드밴드(주)` ·
  `SK브로드밴드` → 같은 업체.

- `(주)○○` · `○○주식회사` · `○○` 같은 **법인 표기 차이는 이력을 나누는
  기준으로 쓰지 않는다.**
- ⛔ **업체명만으로 업체를 동일시하지 않는다.**

**예외 / 주의사항**: 사업자등록번호가 같은데 상호가 **전혀 다른 이름**으로
바뀐 경우에는 상호변경 여부를 확인한다.

**시스템 반영**: **한쪽은 이미 맞고, 한쪽은 고쳐야 합니다.**

| 기능 | 현재 기준 | 판정 |
|---|---|---|
| 구매 ↔ 기업 연결(`CompanyMatcher`) | 사업자등록번호 완전 일치 | ✅ 답변과 일치 |
| 미매칭 기업 조회 | 사업자등록번호로 묶고 여러 표기를 전부 표시 | ✅ 답변과 일치 |
| **거래처 과거 확정 이력**(검토 화면 · `reviews/company_labels.py`) | **거래처명 문자열 완전 일치** | ❌ **답변과 다름** |

⚠️ **이 답변이 열려 있던 결정을 닫습니다.** `company_labels.py` 는 *"어느 쪽으로
묶을지(거래처명 / 사업자번호 / 둘 다)는 **고객 확인 사항**"* 이라고 적어 두고
기다리던 자리였고, 그 문서에 적힌 실측 사례가 **고객이 이번에 드신 예와 같은
건**입니다 — 한 사업자번호가 `SK브로드밴드주식회사` · `SK브로드밴드(주)` ·
`에스케이브로드밴드(주)` · `SK브로드밴드` 네 가지로 적혀 **이력이 나뉘어 실제보다
적게** 보입니다(현재 배치 기준 12종).

⛔ **이번 STEP 에서 고치지 않았습니다.** 문서화 STEP 이고, 이력 묶는 키를 바꾸면
검토 화면의 숫자가 실제로 달라지기 때문입니다. → **다음 STEP 대상**

## QT-7 (원 Q7). 임차료 · `임차` 가 들어간 거래 ✅ **회신 완료 (일부 🔴 남음)**

**질문**: 적요에 `임차` 가 들어간 거래는 어떻게 판정하십니까?

**고객 답변**: 예산과목과 실제 거래 성격에 따라 갈린다.

| 예산과목 | 실제 거래 | 유형 |
|---|---|---|
| `임차료` | 장기 차량 임차 | **용역** |
| `통신비` | 이름에 임차가 있으나 실제는 통신비 | **용역** |
| `차량유지비` | 실제는 **장기 주차비** | **물품** |
| `자산취득비` | 프로그램 임차(소프트웨어) | **물품** |
| `외주용역비` | 보상도우미pro 프로그램 임차 | **물품** |

**확정된 업무규칙**

- ⛔ 예산과목만으로도 확정하지 않는다 — 같은 `임차` 표현이 물품과 용역으로
  갈린다.

**🔴 별도로 분리한 것 두 가지**

1. **단기 차량 임차는 실적에 넣지 않는다** — 고객 답변:
   *"출장지 하루/이틀 차량 렌트는 실적에 들어가지 않아."*
   이는 구매유형이 아니라 **실적 산입 범위**(W-7)의 문제입니다.
   🔴 **W-16 신설** — "단기" 의 경계(며칠까지인가)와 데이터에서 판별하는 방법이
   정해지지 않았습니다. **여쭐 것**: 며칠 이하를 단기로 보십니까? 데이터에서
   장기·단기를 구분할 수 있는 값이 있습니까?

2. **삭제되었어야 할 데이터 2건** — 고객 답변: 아래는 실수로 들어간 데이터다.
   - `민원 담당자 교육(교육비, 임차료, 다과비)`
   - `민원 담당자 교육 2차(강사비, 재료비, 다과비, 임차료)`

   🔴 **W-17 신설.** ⛔ **이 답변을 근거로 DB 를 고치지 않았습니다.** 어떤 행을
   말씀하시는지 특정하는 방법도, 정정 절차도 정해지지 않았습니다. **여쭐 것**:
   이런 건을 앞으로 어떻게 처리할까요(재업로드 · 담당자 표시 · 그 밖)?

**시스템 반영**: 유형 사례는 참고용. W-16 · W-17 은 회신 대기.

## QT-8 (원 Q8). 각종수수료 ✅ **회신 완료**

|---|---|
| 일반적인 수수료 | 용역 |
| 나라장터 **물품 구매** | 물품 |
| 소프트웨어 라이선스 구매 | 물품 |

**확정된 업무규칙**: `각종수수료` 라는 예산과목은 구매유형 판정의 **충분조건이
아니다.** 일반적인 수수료는 용역으로 보되, 물품으로 확정된 사례가 존재한다.

**예외 / 주의사항**: ⚠️ **기존의 `각종수수료 = 무조건 용역` 이해는 폐기한다.**
`세목유형관리` 표(Q5-1)에 그렇게 적혀 있었으나, 고객 답변이 이를 부정했다.
→ **Q5-1 이 "표를 그대로 쓸 수 없다" 로 해소되었다.**

**시스템 반영**: ⛔ 예산과목 단독 규칙을 만들지 않는다.

없습니다.**

**시스템 반영**: ⛔ 업체명 기반 판정을 만들지 않는다.
