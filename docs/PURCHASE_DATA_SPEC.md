# 1. 목적

본 문서는 고객(공공기관)이 제공하는 **구매(지출) 데이터의 최소 요구 규격**을 정의한다.

이 시스템은 고객의 구매 데이터에 외부에서 수집한 기업 인증정보를 결합하여 달성률을 계산한다.
따라서 **구매 데이터에 필수 항목이 빠지면 계산 자체가 불가능**하며,
본 문서는 고객에게 데이터를 요청할 때의 기준서로 사용한다.

> ⚠️ 본 문서는 **초안**이다. 실제 고객 데이터 샘플을 확보한 뒤 v1.0으로 확정한다.
> 기관마다 지출 시스템 양식이 다르므로, 아래 컬럼명은 **의미 기준**이며 헤더명은 매핑으로 처리한다.

# 2. 컬럼 정의

## 2.1 전체 컬럼 목록

| 컬럼 | 필수 여부 | 설명 |
|---|---|---|
| `business_no` (사업자등록번호) | **필수** | 공급업체의 사업자등록번호. 기업·인증 정보와 결합하는 **기준 키** |
| `company_name` (업체명) | **필수** | 공급업체 상호. 매칭 실패 시 확인 및 보조 매칭에 사용 |
| `contract_date` (계약일) | **필수** | 계약을 체결한 날짜. **창업기업** 정책의 판정 기준일 |
| `payment_date` (지급일) | **필수** | 대금을 지급한 날짜(지출완료일). **중소·여성·장애인·녹색제품** 정책의 판정 기준일 |
| `amount` (구매금액) | **필수** | 구매(지출) 금액. 실적 집계 대상 |
| `purchase_name` (품명·건명) | 선택 | 구매 건의 명칭. 검증·소명 자료로 활용 |
| `contract_no` (계약번호) | 선택 | 기관 내부 계약 식별번호. 원본 대조용 |
| `department` (부서명) | 선택 | 구매 부서. 향후 부서별 통계에 활용 |
| `contract_method` (계약방법) | 선택 | 수의계약·경쟁입찰 등. 정책 판정 고도화 시 활용 |
| `item_code` (물품목록번호) | 선택 | 조달청 물품목록번호. **제품 기준 정책** 판정에 필요 |
| `quantity` (수량) | 선택 | 품목 수량. 향후 품목 기준 정책에 필요 |

## 2.2 필수 컬럼 (5개) — 없으면 계산 불가

| 컬럼 | 사용처 | 없을 경우 영향 |
|---|---|---|
| **사업자등록번호** | 기업 매칭 | **모든 정책 계산 불가**. 어떤 기업인지 알 수 없음 |
| **업체명** | 표시·보조 확인 | 매칭 실패 원인 파악 불가 |
| **계약일** | 창업기업 판정 | **창업기업 정책 계산 불가** |
| **지급일** | 일반 정책 판정 | **중소·여성·장애인·녹색제품 계산 불가** |
| **구매금액** | 실적 집계 | **집계 자체 불가** |

> **계약일·지급일이 모두 필수인 이유**
> 정책마다 판정 기준일이 다르기 때문이다. 지급일만 있으면 창업기업을,
> 계약일만 있으면 나머지 정책을 계산할 수 없다.
> 실무에서 한쪽이 누락된 경우가 흔하므로 **데이터 요청 시 가장 먼저 확인해야 할 항목**이다.

## 2.3 선택 컬럼 — 현재 미사용, 향후 확장 대비

| 컬럼 | 향후 용도 |
|---|---|
| 품명·건명, 계약번호 | 감사·소명 자료 생성, 원본 대조 |
| 부서명 | 부서별 통계 (`POLICY_DEFINITION.md` 향후 확장 항목) |
| 계약방법 | 수의계약 여부에 따른 판정 세분화 |
| 물품목록번호, 수량 | **제품 기준 정책** 판정 (녹색제품 품목 단위, 자활용사촌 등) |

> 선택 컬럼은 **지금 당장 필요하지 않지만**, 확보해 두면 향후 재요청 없이 확장할 수 있다.
> 고객에게 요청할 때 "가능하면 함께 제공" 수준으로 안내하는 것을 권장한다.

# 3. 데이터 형식 규칙

## 3.1 사업자등록번호

| 항목 | 내용 |
|---|---|
| 허용 입력 | `123-45-67890`, `1234567890` |
| 저장 형식 | 하이픈 제거 10자리 숫자 문자열 |
| 주의 | **숫자형으로 변환 금지** — 앞자리 `0`이 사라짐. Excel에서 특히 빈번한 오류 |

## 3.2 날짜

| 항목 | 내용 |
|---|---|
| 권장 형식 | `YYYY-MM-DD` |
| 허용 검토 | `YYYYMMDD`, `YYYY/MM/DD`, Excel 날짜 셀 |
| 주의 | 텍스트/날짜 셀이 섞여 있는 경우가 많아 **파싱 규칙 필요** |

## 3.3 금액

| 항목 | 내용 |
|---|---|
| 권장 형식 | 숫자만 (`3000000`) |
| 허용 검토 | 천단위 구분(`3,000,000`), 통화기호 |
| 처리 원칙 | **`Decimal`로 처리**, 부동소수 사용 금지 |
| 제약 | **0보다 커야 함** (0 이하는 오류 처리) |
| 확인 필요 | **부가세 포함 여부**, 취소·반품 건의 음수 표기 여부 |

# 4. 검증 규칙 (제안)

업로드 시 아래를 검증하고, 실패 건은 사유와 함께 보고한다.

| 구분 | 규칙 | 처리 |
|---|---|---|
| 필수 | 5개 필수 컬럼 존재 | 없으면 **전체 거부** |
| 형식 | 사업자번호 10자리 숫자 | 오류 행 보고 |
| 형식 | 날짜 파싱 가능 | 오류 행 보고 |
| 값 | 금액 > 0 | 오류 행 보고 |
| 논리 | 계약일 ≤ 지급일 | **경고**(역전 사례가 실제로 존재할 수 있음) |
| 매칭 | 사업자번호로 기업 조회 | 실패 시 정책 실적 제외, **전체 구매액에는 포함** |

> **매칭 실패 처리 원칙**: 매칭에 실패한 구매는 `company_id`가 비어 있는 상태로 저장되며,
> 정책 실적으로는 인정되지 않지만 **전체 구매액(분모)에는 포함**된다.
> 따라서 매칭률이 낮으면 달성률이 실제보다 낮게 나온다 — **매칭률 리포트가 필요**하다.

# 5. 파일 규격 (제안)

# 7. 확정 전 확인 사항

고객 데이터 샘플 확보 시 아래를 반드시 확인한다.

| # | 확인 항목 | 이유 |
|---|---|---|
| 1 | **지급일 컬럼이 실제로 존재하는가** | 없으면 MVP 4개 정책 계산 불가 — 최대 리스크 |
| 2 | 금액의 **부가세 포함 여부** | 실적 기준 정의에 영향 |
| 3 | 취소·반품 건의 표기 방식 | 음수·별도 플래그 여부 |
| 4 | 한 계약이 여러 행으로 분할되는가 | 중복 집계 방지 |
| 5 | 사업자번호 **누락 비율** | 매칭률 및 정확도에 직결 |
| 6 | 연도·회계기간 구분 방식 | 집계 기간 정의 |
| 7 | 데이터 제공 주기 | 수집·갱신 설계에 영향 |

# 8. 요약

- **필수 5개 컬럼**: 사업자등록번호 · 업체명 · 계약일 · 지급일 · 구매금액
- 그중 실무 리스크가 가장 큰 항목은 **지급일**이다(누락 사례가 흔함).
- 선택 컬럼은 지금 쓰지 않지만, **재요청 비용을 줄이기 위해 함께 확보**할 것을 권장한다.
- 본 규격은 고객 데이터 샘플 확보 후 v1.0으로 확정한다.
