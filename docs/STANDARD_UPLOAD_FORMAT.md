# 1. 왜 표준 양식인가

현재는 기관이 준 매입매출장(88개 컬럼)을 직접 해석해야 한다. 그 방식은 다음 문제가 있다.

| 문제 | 실측 근거 |
|---|---|
| 필요한 컬럼이 **없다** | 계약일자 · 대표자명 · 구매유형 — 88개 중 0건 |
| 컬럼 의미가 **불명확하다** | 날짜만 4종(`신고기준일`·`기표일자`·`결의일자`·`발행일`) |
| 대부분이 **구매가 아니다** | 2,903행 중 매출이 79.4% |
| 기관마다 **양식이 다르다** | 컬럼명이 바뀌면 시스템 전체가 영향받음 |

→ **사용자가 우리 양식에 맞춰 입력**하면 위 4가지가 한 번에 사라진다.

## 1.1 목표 구조

```text
표준 Excel  →  Validation  →  Mapping  →  Purchase Model  →  Repository  →  Calculator
   (사용자 입력)                              (내부 계산용)
```

**핵심 원칙**: 업로드 컬럼이 바뀌어도 Calculator 가 영향받지 않는다.
Mapping 계층이 그 사이를 흡수한다.

# 3. 🔴 가장 중요한 미결정 — 결의일자를 어느 필드에 담는가

현재 `Purchase` 모델의 날짜는 둘뿐이다.

| 필드 | 현재 정의 |
|---|---|
| `payment_date` | "대금 지급일(지출완료). 일반 정책 판정 기준일" |
| `contract_date` | "계약일. 창업기업 정책 판정 기준일" |

고객이 확정한 것은 **"산정 기준일이 결의일자"** 이지, **"결의일자 = 대금 지급 완료일"**
이 아니다. 두 진술은 다르다.

| 안 | 내용 | 장단점 |
|---|---|---|
| **①** | `payment_date` 를 그대로 사용 | 변경 0줄. **필드 이름이 실제 의미와 어긋남** |
| **②** | `resolution_date` 신규 필드 | 의미가 정확. **스키마 변경 + 마이그레이션 + `PeriodFilter` 확장** |
| **③** | `payment_date` 를 "실적 산정 기준일" 로 **재정의** | 문서만 수정. 나중에 진짜 지급일이 필요해지면 재작업 |

> **표준 양식을 새로 만드는 지금이 ②를 도입할 최적기다.** 원본 컬럼 해석을
> 버리고 우리 양식으로 가는 시점이므로, 필드 의미를 정확히 맞춰 둘 수 있다.
> 다만 **스키마 변경은 PM 승인 대상**이므로 임의로 진행하지 않았다.

**참고**: 창업기업 OR 규칙은 이 결정과 **무관하게 이미 동작한다.**
`PaymentOrContractDateRule` 이 특정 날짜를 "결의일자" 라고 단정하지 않고
두 날짜 필드를 모두 보기 때문이다.

# 5. 🔴 음수 금액 — 저장 자체가 막혀 있다

고객 확정 규칙(§0.6.3)에 따라 상계 로직은 구현했다(`core/offsetting.py`).
그러나 현재 `PurchaseRepository._validate()` 가 **`amount <= 0` 저장을 거부**한다.

```
음수 거래 → 저장 거부 → DB 에 없음 → 상계할 대상이 없음
```

| 선택지 | 영향 |
|---|---|
| ① 현행 유지 | 음수 행을 업로드 오류로 처리. **상계 규칙이 영원히 동작하지 않음** |
| ② 저장 허용 | D-003(원본 보존)과 일치. **C-2 충돌 해소 · Issue #49** |
| ③ 업로드 시점에 상계 | 원본이 남지 않아 추적 불가 |

**②가 확정 업무규칙과 일치**하지만, Repository 검증 변경은 승인 대상이라
진행하지 않았다. 영향 범위는 `Purchase` 모델 · Repository 검증 · Importer ·
Calculator · 기존 테스트 · 0원 거래 처리다.

# 7. 확정 / 미확정 요약

## ✅ 확정

- 구매실적 기준일 = **결의일자** (일반 정책)
- 창업기업 = **결의일자 OR 계약일자**가 인증 유효기간에 해당하면 인정
- 구매금액 = **VAT 포함 총액** (원본의 `계`)
- 음수 상계 판별 = **기업명 + 사업자번호 + 절대금액 + 이전 거래**
- 구매유형 3건 — 도서인쇄비/소모성물품구입비 → `GOODS`, 임차료 → `SERVICE`
- 표준 양식을 **우리가 지정**하는 방향

## 🔴 미확정

- 결의일자를 담을 **내부 필드** (§3)
- 표준 양식의 **실제 컬럼명 · 필수여부 · 날짜/금액 형식**
- 계약일자 **원본 파일 · 연결 키** (W-2-1)
- 확정 3건 외 **예산과목 구매유형**
- **음수 저장 제약** 해제 여부 (§5)
- `Purchase.purchase_type` **필드 신설** 승인
- 중복 행 판정 기준
- openpyxl 의존성 추가
