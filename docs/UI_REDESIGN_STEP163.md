# 1. 먼저 보고드릴 제약 두 가지

## 1.1 웹폰트를 인터넷에서 받아올 수 없습니다

이 프로그램은 **폐쇄망에서 동작하는 것이 요구사항**이고, 그것을 지키는지
시험이 감시하고 있습니다.

    [OK] 외부 리소스 미사용 — 오프라인·폐쇄망에서도 동작   (verify-backend)

지시하신 Pretendard · Noto Sans KR · Noto Serif KR 을 쓰려면 **글꼴 파일을
설치본 안에 넣어야** 합니다. Google Fonts 링크를 넣으면 위 시험이 깨지고,
기관 내부망에서는 글꼴이 **적용되지 않은 채** 화면이 뜹니다.

| 방법 | 설치본 증가(추정) | 비고 |
|---|---|---|
| Pretendard 서브셋(한글 상용 + 숫자) woff2 2종(Regular/Bold) | 약 1.5 ~ 3 MB | ⭐ 권고 |
| Pretendard 전체 9종 | 약 15 ~ 25 MB | 과함 |
| Noto Sans KR + Noto Serif KR 동봉 | 추가 5 ~ 10 MB | 장문용이 실제로 필요한지 먼저 확인 |

현재 화면은 이미 `font-family: "Pretendard", "Malgun Gothic", …` 로 **Pretendard 를
먼저 찾고 있습니다.** 담당자 PC 에 설치돼 있지 않아 맑은 고딕으로 떨어질 뿐입니다.

> ❓ **[결정 1]** 글꼴 파일을 설치본에 동봉할까요? 동봉한다면 어느 범위까지
> (Pretendard 2종만 / Noto 계열까지)?
> ⛔ 결정 전에는 글꼴 파일을 넣지 않겠습니다.

# 2. As-Is 분석

## 2.1 한눈에 보기

| 화면 | 현재 문제점 | 사용자 혼란 가능성 | 개선 방향 |
|---|---|---|---|
| **실적(대시보드)** | 표 8행 중 6행이 «—» 로 비어 있고, 아래 바로가기 6개가 **모두 같은 굵기** | 「지금 뭘 해야 하지?」 — 다음 행동이 여섯 갈래로 흩어짐 | 다음 할 일 **하나**를 카드로 크게. 나머지는 접기 |
| **실적** | 「6종·기업정보가 없어 계산하지 못했습니다」 안내가 표 **아래**에 있음 | 표를 먼저 읽고 「0%인가?」 오해한 뒤에야 이유를 만남 | 이유를 표 **위**로. 표에는 「등록하면 계산됩니다」 |
| **자료 관리** | 한 탭에 카드 6개가 **세로 6,000px** 로 이어짐(목표비율 · 업로드 · 기업정보 · 확인방식 · 이력 · 검토) | 어디가 시작이고 어디가 끝인지 모름. 스크롤 중 길을 잃음 | 업무 **순서 4단계**로 나누고 한 번에 한 단계만 |
| **구매실적 업로드** | 「검증만」과 「검증 후 저장」이 **똑같이 생김**. 둘 다 처음엔 비활성인데 **이유가 없음** | 어느 것이 진짜 저장인지, 왜 눌리지 않는지 알 수 없음 | 저장을 유일한 주 CTA 로. 비활성 사유를 옆에 글로 |
| **업로드 결과** | 「전체 / 저장 / 미적재」 숫자 3개와 오류 표가 같은 크기 | 성공인지 실패인지 한눈에 안 들어옴 | 결과 한 줄 판정(성공/부분/실패)을 가장 크게 |
| **기업정보 등록** | 정책 8종 × (방법 · 파일 선택 · 등록) = **한 표에 24개 이상 컨트롤** | 어느 정책부터 해야 하는지, 몇 개나 남았는지 모름 | 「N / 8 등록됨」 진행률 + 미등록만 먼저 보이기 |
| **구매유형 검토** | 한 건이 **카드 하나**인데 그 안에 소제목이 8개. 같은 안내문이 **모든 행에 반복** | 진짜 눌러야 할 것(유형 고르기·확정)이 설명에 묻힘 | 한 줄 = 한 결정. 설명은 카드 밖 안내 1회로 |
| **구매유형 검토** | 거르개 **12개**가 두 줄로 깔림(기간·검색·정책·상태·확정여부·과거이력·후보수·정렬·방향·페이지크기·확정자·새로고침) | 처음 오면 무엇부터 만져야 할지 모름 | 기본 3개만 노출 + 「자세한 조건」 접기 |
| **점검** | KPI 4 + 막대 + 빈 표 + 적재표 + 월별 + 게이지 + 정책 9카드 + 미매칭 표 | 정보는 많은데 **판단할 것**이 없음 | 「확인이 필요한 것」만 위로, 나머지는 접기 |
| **미매칭 기업** | 거래처명이 2~3줄로 접힘, 열 너비 고정 | 표가 읽기 어렵고 세로로 길어짐 | 한 줄 말줄임 + 마우스 올리면 전체 |
| **공통** | 단추 **55개가 전부 같은 `.control` 클래스** | 중요한 것과 보조가 구분되지 않음 | 주 CTA / 보조 / 위험 3단계로 분리 |
| **공통** | 되돌리기 어려운 작업(배치 교체·확정 취소)이 다른 단추와 같은 모양 | 실수로 누를 수 있음 | 위험 단추는 색·문구·확인 절차 분리 |
| **공통** | 도움말이 **PDF 매뉴얼 한 덩어리** | 화면을 보며 따라 할 수 없음 | 화면 위 하이라이트 온보딩 |

## 2.2 잘 되어 있어 **유지할** 것

⛔ 다음은 건드리지 않겠습니다. 이미 이 시스템의 강점입니다.

- 상태를 **색으로만** 말하지 않습니다 — 「부족」 「계산 보류」 「기업정보 미등록」
  처럼 배지에 글자가 함께 있습니다(색각 이상에도 읽힙니다).
- 「—」와 「0%」를 **구분**합니다. 모르는 것을 0 으로 적지 않습니다.
- 「원본(DB-1 · 수정되지 않습니다)」처럼 **무엇이 원본인지** 밝힙니다.
- 탭에 `role="tablist"` · `aria-labelledby` 가 붙어 있습니다.
- 안내 문구가 업무 용어로 쓰여 있습니다(「미등록과 미해당은 다릅니다」).

# 5. CTA · 의사결정 영역 설계

## 5.1 단추 3단계

| 단계 | 쓰는 곳 | 모양 |
|---|---|---|
| **주 CTA** | 화면당 **하나**. 검증 후 저장 · 확정 저장 · 기업 명단 등록 | 진한 배경, 흰 글자, 조금 크게 |
| 보조 | 검증만 · 새로고침 · CSV 내려받기 · 이력 보기 | 지금처럼 테두리만 |
| 위험 | 확정 취소 · 기존 자료 교체 · 실적 제외 | 붉은 테두리 + 글자, **확인 창 필수** |

⛔ 색만으로 구분하지 않습니다. 위험 단추에는 「되돌리려면 다시 확정해야
합니다」처럼 **결과를 적습니다.**

# 6. 하이라이트 온보딩 설계

## 6.1 동작

- 첫 실행 때 자동으로 시작, **건너뛰기** 항상 표시
- 끝냈거나 건너뛰면 `localStorage` 에 기록하고 **다시 자동 시작하지 않음**
- 오른쪽 위 **[도움말]** 로 언제든 다시 실행
- 대상 요소를 밝게, 나머지는 어둡게. 다음 / 이전 / 건너뛰기
- 대상이 화면 밖이면 **스크롤해서 보여 준 뒤** 하이라이트
- 대상이 **없으면 그 단계를 건너뛰고** 다음으로 (화면이 바뀌어도 멈추지 않음)
- 창 크기가 바뀌면 위치를 다시 계산

## 6.2 첫 안내 6단계 (실적 → 자료 관리)

1. 「여기서 연도를 고릅니다」 — 연도 선택
2. 「지금 하실 일이 여기에 뜹니다」 — 주 CTA 카드
3. 「정책마다 목표·실적·상태를 봅니다. «—» 는 0%가 아닙니다」 — 표
4. 「자료는 여기서 넣습니다」 — 자료 관리 탭
5. 「원본을 고르고 연도를 고른 뒤 저장합니다」 — 업로드 카드
6. 「구매유형은 여기서 확정합니다」 — 검토 카드

## 6.3 안전장치 (지시서 §5 주의사항)

⛔ 온보딩 코드가 **업무 화면을 막지 않도록** 합니다.

- 전체를 `try/catch` 로 감싸고, 실패하면 **조용히 종료**하고 화면은 그대로
- `localStorage` 접근 실패(정책 차단 등)도 잡아서 무시
- 온보딩 레이어에 `Esc` 로 즉시 종료
- 온보딩이 켜져 있어도 **기존 단추는 계속 눌립니다**(읽기 전용 안내)

# 10. 진행 제안

```
 [1] As-Is 분석 · To-Be 시안          ← 지금 여기 (이 문서)
      ↓  PM 검토 · 방향 확정
 [2] 실적 대시보드 + 구매유형 검토 실제 수정
      ↓  화면 캡처로 전후 비교 보고
 [3] 나머지 화면에 공통 디자인 적용
      ↓
 [4] 온보딩 적용
      ↓
 [5] 전체 시험 · 반응형 · 접근성 확인 · 최종 보고
```

각 단계가 끝날 때마다 캡처와 함께 보고드리고, ⛔ 한꺼번에 커밋하지
않겠습니다.
