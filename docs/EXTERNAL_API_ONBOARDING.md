# 1. 목적

외부 인증 데이터를 수집하기 위한 **API 활용신청 절차**를 정리한다.
개발과 별개로 **지금 바로 착수할 수 있는 행정 절차**이며, 승인에 시간이 걸리므로
조기 신청이 필요하다.

## ⚠️ 보안 원칙 (필수 준수)

> **실제 인증키를 코드·GitHub·문서에 저장하지 않는다.**

| 구분 | 방침 |
|---|---|
| 저장 위치 | `.env` 파일 (이미 `.gitignore` 로 제외됨) |
| 코드 접근 | 환경변수로만 읽는다 |
| 문서 기재 | 키 값 자체는 **절대 기재 금지**. 발급 여부·담당자만 기록 |
| 공유 방법 | 별도 보안 채널. 이슈·PR 코멘트에 붙여넣지 않는다 |

권장 환경변수 이름(값은 각자 `.env` 에 보관):

```
SMPP_API_KEY=          # 공공구매종합정보망 인증서 API
STARTUP_API_KEY=       # 창업진흥원 창업기업확인서 API
SME_API_KEY=           # 중소벤처24 (중소기업)
```

# 3. 신청 대상별 상세

## 3.1 [1순위] 중소벤처24 Open API — 중소기업

| 항목 | 내용 |
|---|---|
| **제공기관** | 중소벤처기업부 / 중소기업기술정보진흥원(TIPA) |
| **신청 URL** | https://www.smes.go.kr/main/dbCnrs (중소벤처24 Open API 안내) |
| **신청 방식** | **인증키 신청서 제출 → 담당자 검토 → 이메일로 인증키 회신** |
| **인증키 발급** | **심사·승인제** (자동 발급 아님) |
| **문의처** | 중소벤처24 운영팀 042-388-0370 / 042-388-0371, smeshelp@tipa.or.kr |
| **필요 정보(예상)** | 기관·사업자 정보, 담당자 연락처, 활용 목적, 시스템 개요, 예상 호출량 |
| **예상 승인 절차** | 신청서 접수 → 활용 목적 검토 → 가능 여부 판단 → 인증키 회신 |
| **신뢰도** | 🔶 공개 안내 기준. **세부 요건은 문의 확인 필요** |

### ⚠️ 최대 리스크

- 인증·확인서 서비스 API는 **검증된 플랫폼 사업자 위주로 제공**된다는 안내가 있어,
  **신청이 반려될 가능성**이 있다.
- 중소기업은 MVP 5종 중 **비중이 가장 큰 정책**이므로, 반려 시 영향이 크다.

### 반려 대비 대체 경로 (사전 검토 필요)

| 대안 | 내용 |
|---|---|
| A | 고객 기관이 **중소기업확인서 사본**을 수집해 제공 → 일괄 등록 |
| B | 고객 기관이 보유한 기존 확인 결과 활용 |
| C | 공공구매종합정보망 경로로 확인 가능한지 재조사 |

> **선행 확인 사항**: 신청 전 문의처에 **"민간 시스템도 신청 가능한지"** 를 먼저 확인하면
> 불필요한 신청 절차를 줄일 수 있다.

## 3.2 [2순위] 공공구매종합정보망(SMPP) 인증서 API — 여성기업·장애인기업

| 항목 | 내용 |
|---|---|
| **제공기관** | 주식회사 한국중소벤처기업유통원 |
| **데이터셋명** | 공공구매종합정보망 인증서 정보 제공 서비스 |
| **신청 URL** | https://www.data.go.kr/data/15062581/openapi.do |
| **신청 방식** | 공공데이터포털 **회원가입 → 활용신청** |
| **인증키 발급** | 포털에서 발급받는 **일반 인증키(Encoding/Decoding)** |
| **필요 정보** | 포털 계정, 활용 목적, 시스템 정보 |
| **예상 승인 절차** | 활용신청 → (자동 또는 담당자 승인) → 인증키 사용 가능 |
| **응답 형식** | REST API (JSON / XML) |
| **신뢰도** | ✅ 데이터셋 존재·조회 조건 확인. 🔶 응답 필드는 미검증 |

### 확인된 조회 조건

- **사업자등록번호 + 기준일자**로 조회
- **여성기업확인서 · 장애인기업확인서 · 직접생산확인증명서** 상세정보 제공

> **본 프로젝트와 정합성이 가장 높은 API다.** 판정 기준일을 파라미터로 넘길 수 있어
> "기준일에 인증이 유효했는가" 판정 구조와 그대로 맞는다.
> **하나의 API로 2개 정책(여성·장애인)을 처리**할 수 있어 우선 착수 대상으로 적합하다.

### 승인 후 즉시 확인할 항목

| # | 확인 항목 | 이유 |
|---|---|---|
| 1 | 응답에 **유효기간(시작일·종료일)** 이 있는가 | 없으면 판정 불가 |
| 2 | 인증서 번호·발급기관 제공 여부 | `certificate_number`·`issuing_agency` 매핑 |
| 3 | **대표자명** 제공 여부 | `Company.representative_name` nullable 결정과 연결 |
| 4 | 일일 호출 한도 | 수집 주기 설계 |
| 5 | 조회 실패(미인증 기업) 시 응답 형태 | 오류 처리 설계 |

| # | 확인 항목 | 이유 |

# 4. 공통 신청 절차 (공공데이터포털)

2·3순위는 동일한 절차를 따른다.

```
[1] 공공데이터포털(data.go.kr) 회원가입
        ↓
[2] 대상 데이터셋 페이지 접속
        ↓
[3] "활용신청" 클릭 → 활용 목적·시스템 정보 입력
        ↓
[4] 승인 (자동 승인 또는 담당자 검토)
        ↓
[5] 마이페이지에서 인증키 확인
        ↓
[6] .env 에 저장 (GitHub 커밋 금지)
        ↓
[7] 응답 샘플 확보 → 필드 검증 → 문서 갱신
```

## 4.1 신청 시 준비할 정보

| 항목 | 내용 |
|---|---|
| 활용 목적 | 공공기관 우선구매 정책 달성률 자동 계산 |
| 활용 형태 | 시스템 내부 조회 (재배포 없음) |
| 담당자 | 이름·연락처·이메일 |
| 예상 호출량 | 구매 데이터 규모에 따라 산정 (고객 데이터 확보 후 구체화) |

## 4.2 이용약관 확인 필요 항목

- **수집 데이터의 저장(캐싱) 허용 여부** — 본 시스템은 인증정보를 DB에 저장한다
- 재배포·제3자 제공 제한
- 출처 표시 의무

> 저장이 제한되는 API가 있다면 **매 계산 시 조회하는 방식**으로 설계를 바꿔야 하므로,
> 승인 후 약관을 반드시 확인한다.

# 5. 실제 응답 필드 확인 방법

인증키 발급 후, 아래 순서로 응답을 검증한다.

| 순서 | 방법 |
|---|---|
| 1 | 포털 데이터셋 페이지의 **"미리보기 / OpenAPI 실행"** 기능으로 즉시 확인 |
| 2 | 포털 제공 **활용가이드(참고문서)** 에서 요청·응답 명세 확인 |
| 3 | 실제 사업자번호로 호출해 **응답 샘플 확보** |
| 4 | 샘플을 `DATA_MAPPING.md` 표준 컬럼과 대조 |
| 5 | 검증 결과로 `DATA_COLLECTION_STRATEGY.md` 를 v1.1 로 갱신 |

> 🔒 응답 샘플을 문서화할 때 **인증키가 포함된 요청 URL 전체를 붙여넣지 않는다.**
> 키 부분은 반드시 마스킹한다.

# 8. 요약

- **지금 바로 착수 가능**한 행정 절차이며, 고객 데이터 확보와 무관하게 진행할 수 있다.
- **중소벤처24가 최우선** — 심사제라 리드타임이 가장 길고, 반려 가능성도 있다.
- **SMPP API가 정합성 최고** — 사업자번호+기준일자 조회로 2개 정책을 동시에 처리한다.
- 인증키는 **`.env` 에만 보관**하며 코드·문서·GitHub에 저장하지 않는다.
- 승인 후 **응답 필드 검증**을 마쳐야 Collector 구현에 착수할 수 있다.
