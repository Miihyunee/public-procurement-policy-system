# 1. Q5-1 — `세목유형관리` 표는 공식 업무규칙인가?

| 답변 | 시스템에 미치는 영향 | 준비된 것 | 새로 할 일 |
|---|---|---|---|
| **(a) 공식 업무규칙이다** | 유형 판정의 **주 경로가 예산과목 표 조회**가 된다. 적요 분석은 표가 답을 못 주는 **외주용역비 270건에만** 적용된다 | `core/purchase_type.py` 에 확정 3건이 이미 표 형태(`CONFIRMED_BUDGET_ACCOUNT_TYPES`)로 있음 — 같은 구조를 확장하면 됨 | 표 12세목 + 삭제 규칙 + 거래처 예외를 데이터로 등록 · 적용 순서 결정(결정 대기 ③) |
| **(b) 담당자 개인 메모다** | 표를 **코드로 옮기지 않는다.** 적요 분석이 1,744건 전체를 대상으로 해야 하며, 실측상 기준선 대비 이득이 크지 않다(§9) | 세 분석기가 이미 전체 대상으로 동작 | 코퍼스를 무엇으로 할지 다시 물어야 함 → **막힘** |
| **(c) 일부만 공식이다** | 공식인 세목만 표로, 나머지는 검토 대상으로 | 위 (a) 와 같은 구조 | 어느 세목이 공식인지 목록 필요 |

> 🔴 **(b) 인 경우가 가장 곤란합니다.** 작업본 `구분` 이 그 메모의 결과물이므로,
> 코퍼스로 쓸 근거가 사라집니다. 그때는 담당자가 검토 화면에서 확정 사례를
> 처음부터 쌓아야 하며(cold start), 그 흐름은 이미 동작합니다.

# 2. Q5-2 — 구매유형 판단에 `거래처명`을 함께 써도 되는가?

| 답변 | 영향 | 준비된 것 | 새로 할 일 |
|---|---|---|---|
| **(a) 써도 된다** | 결정력이 크게 오른다 — 적요 단독 58행 불가 → **0행**. 다만 `DescriptionClassifier` 의 입력이 문자열 하나라는 전제가 깨진다 | 인터페이스가 `Protocol` 이라 **상위 계층은 그대로** 두고 구현체만 바꾸면 됨 | `classify()` 시그니처 확장(입력 객체 도입) · 세 분석기 재구현 · 재측정 |
| **(b) 적요만 봐라** | 현재 구조 유지. 적요 단독 상한 98.97% 가 천장 | 전부 그대로 | 없음 |
| **(c) 화면에 보여주되 분석에는 쓰지 마라** | 담당자가 눈으로 참고 | ✅ **이미 됨** — 검토 화면에 거래처명·사업자번호가 표시됨 | 없음 |

> **(c) 가 현재 상태입니다.** 거래처명은 화면에 있고, 분석기 입력에는 없습니다.

# 3. Q5-3 — 적요가 지출결의서 단위로 반복되는 것이 정상인가?

| 답변 | 영향 | 준비된 것 | 새로 할 일 |
|---|---|---|---|
| **(a) 정상이다** | 검토 단위를 **행이 아니라 결의서 묶음**으로 바꾸는 것이 맞다. 같은 적요 여러 행을 한 화면에서 보고 각각 다른 유형을 줄 수 있어야 함 | 그룹핑 후보 키 5종 조사 + **그룹별 일관성 실측 완료**(`DESCRIPTION_GROUPING_ANALYSIS.md` §2·§8) · 과거 이력 블록이 이미 "같은 적요가 갈렸음" 을 표시 | 그룹핑 키 확정 → 목록 API 에 그룹 파라미터 추가 → 화면 그룹 뷰 |
| **(b) 비정상 · 정리 대상이다** | 적요를 행 단위로 다시 적는 업무 개선이 선행 | — | 원본 데이터 정비 요청 |
| **(c) 정상이지만 그룹으로 볼 필요 없다** | 현재 행 단위 화면 유지 | ✅ 이미 됨 | 없음 |

# 4. Q5-4 — `차량유지비 / 주차비 → 물품`이 맞는가?

| 답변 | 영향 | 준비된 것 | 새로 할 일 |
|---|---|---|---|
| **(a) 맞다** | 해당 46건이 물품으로 확정. 여성기업 목표율 **5%** 구간 | 유형값 자체는 기존 3값 그대로 | Q5-1 과 함께 표에 반영 |
| **(b) 용역이 맞다** | 46건이 용역으로 이동. 목표율은 같은 5% 라 **달성률 영향은 유형별 분모 구성에서만** 발생 | 〃 | 〃 · 과거 확정분 재검토 필요 |

| 답변 | 영향 | 준비된 것 | 새로 할 일 |
|---|---|---|---|
| **(a) 제외가 맞다** | 달성률 **분모가 줄어든다** → 달성률이 올라감. 제외 사유를 데이터로 남겨야 함 | Import Batch 의 `ACTIVE`/`SUPERSEDED` 패턴이 이미 있음 — 물리 삭제 없이 제외 표기 가능 | 제외 사유 컬럼 또는 제외 규칙 등록 · DB-3 설계에 반영(STEP 7) |

| **(c) 일부만 제외** | 제외 사유별로 판단 | 〃 | 사유별 목록 필요 |

> 🔴 이 답변은 **달성률 숫자를 직접 바꿉니다.** STEP 8(Calculator 연결) 전에
> 반드시 확정되어야 합니다.
