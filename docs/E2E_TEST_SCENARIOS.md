# 1. 목적

**외부 API 인증키와 고객 실데이터가 없어도 계산 엔진 전체를 검증**하기 위한 시나리오다.

검증 대상 흐름:

```
구매데이터
  → 사업자번호 정규화
  → Company 매칭
  → Certification 연결
  → 판정 기준일 결정
  → 인증 유효성 판단
  → 구매금액 집계
  → 목표율 적용
  → 달성률 계산
  → Dashboard 표시
```

## 1.1 데이터 사용 원칙 (중요)

| 원칙 | 내용 |
|---|---|
| **pytest 전용** | 여기서 만드는 기업·인증 데이터는 **테스트 Fixture** 다 |
| **운영 데이터 아님** | Bootstrap seed 나 운영 DB 에 **넣지 않는다** |
| **실데이터 흉내 금지** | 대량 샘플을 만들지 않는다. 구조 검증에 필요한 최소 구성만 사용 |
| **가정 명시** | 인증데이터가 "확보되었다고 가정"한 상태의 계산 동작만 검증한다 |

> 실제 인증정보는 외부 API 에서 수집해야 하며, **그 경로는 아직 없다.**
> 본 시나리오는 그 데이터가 들어왔을 때 **계산 엔진이 정상 동작함을 미리 증명**한다.

# 3. 시나리오 A — 중소기업 (지급일 기준)

## 전제 데이터

| 구분 | 값 |
|---|---|
| 기업 | `1018116293` |
| 정책 | `SMALL_BUSINESS`, `PAYMENT_DATE`, 목표율 **50%** |
| 인증 | 2026-01-01 ~ 2026-12-31 |
| 구매 ① | 지급일 2026-03-15, **3,000,000** (하이픈 표기) |
| 구매 ② | 미등록 기업, 7,000,000 |

## 기대 결과

| 항목 | 값 |
|---|---|
| 전체 구매액 | 10,000,000 |
| 정책 구매액 | 3,000,000 |
| 정책 구매비율 | 30% |
| **달성률** | **60.00%** (30% ÷ 50%) |
| 부족률 | 40.00% |
| 상태 | `SHORTAGE` / 부족 |

## 검증 항목
- 전체 흐름이 달성률까지 이어지는가
- 미등록 기업 구매가 **분모에는 포함**되는가
- 하이픈 표기가 정규화되어 매칭되었는가

**결과: ✅ 통과**

# 5. 시나리오 C — 창업기업 (**계약일** 기준) ⭐

> **가장 중요한 시나리오.** 창업기업은 지급일이 아니라 **계약일**로 판정한다.

## 전제 데이터

| 구분 | 값 |
|---|---|
| 정책 | `STARTUP`, **`CONTRACT_DATE`**, 목표율 20% |
| 인증 | 2026-01-01 ~ **2026-06-30** |

| 구매 | 계약일 | 지급일 | 금액 | 판정 |
|---|---|---|---|---|
| ① | **2026-05-01 (유효)** | 2026-08-01 (만료 후) | 2,000,000 | ✅ **인정** |
| ② | 2026-08-01 (만료 후) | **2026-05-01 (유효)** | 3,000,000 | ❌ **제외** |
| ③ | — | — | 5,000,000 (미등록 기업) | 분모만 |

**두 구매의 날짜가 서로 반대**이므로, 지급일로 판정했다면 결과가 뒤바뀐다.

## 기대 결과

| 항목 | 값 |
|---|---|
| 정책 구매액 | **2,000,000** (지급일 기준이었다면 3,000,000) |
| 달성률 | 100.00% (20% ÷ 20%) |

## 검증 항목
- 계약일이 유효기간 내인 구매만 집계되는가
- **지급일 기준으로 계산했을 때의 값(3,000,000)이 아님**을 확인

**결과: ✅ 통과**

# 7. 시나리오 E — 미매칭 후 재매칭

> 구매데이터가 먼저 들어오고 기업정보가 나중에 확보되는 **실제 운영에서 흔한 상황**.

## 단계별 흐름

| 단계 | 동작 | 확인 |
|---|---|---|
| ① | 구매데이터만 Import | 저장됨, `company_id = NULL` (**미매칭 보관**) |
| ② | — | **Company 를 자동 생성하지 않음** (방안 C) |
| ③ | Dashboard 조회 | 정책 구매액 `0` |
| ④ | 기업·인증정보 확보 | 외부 수집 상황 재현 |
| ⑤ | **`rematch()`** 실행 | 1건 연결 |
| ⑥ | Dashboard 재조회 | 정책 구매액 5,000,000, 달성률 **100.00%**, `NORMAL` |

## 유입 순서 무관성 확인
**기업정보를 먼저 넣은 경우와 결과가 동일**해야 한다. → 검증 완료.

**결과: ✅ 통과**

## 9.1 이 시나리오가 증명하는 것

✅ **계산 엔진은 실제 데이터가 들어오면 동작한다.**

기업·인증·구매·목표율이 모두 갖춰지면, 사업자번호 정규화부터 Dashboard 표시까지
**코드 변경 없이** 달성률이 산출된다.

## 9.2 이 시나리오가 증명하지 못하는 것

❌ **실제 데이터로 동작한다는 보장은 아니다.**

| 미검증 항목 | 이유 |
|---|---|
| 실제 API 응답을 DB 에 넣을 수 있는가 | **응답 필드 미확인** |
| 실제 고객 파일을 읽을 수 있는가 | **파일 형식 미확인** |
| 실제 목표율로 계산했을 때 맞는가 | **법정 목표율 미확정** |
| 대량 데이터에서의 성능 | 실데이터 규모 미확인 |
