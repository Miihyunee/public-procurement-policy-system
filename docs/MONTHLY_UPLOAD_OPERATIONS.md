# 0. 매월 하는 일 (한눈에)

```
① 그 달 원본 Excel 을 내려받는다
② 업로드 화면에서 파일을 고르고 대상 연도를 지정 → 검증 → 저장
③ 업로드 결과 확인 — 원본 · 적재 · 미적재 · 설명되지 않는 행
④ 원본과 대조 — [미적재 행 확인] · [미적재 CSV 내려받기]
⑤ 검토 화면에서 **그 달 기간을 선택**
⑥ 검토 — 검색·필터·정렬로 좁혀 가며 확정
⑦ 파일이 잘못됐으면 같은 기간으로 다시 업로드
⑧ 재업로드하면 이전 배치는 이력으로 남고, 최신 배치만 현재 데이터가 된다
```

⑤~⑥ 의 기간 선택은 STEP 15 에서 붙었습니다 — §4.4 참고.

# 1. 한 달치 올리기

```
담당자가 그 달 원본 Excel 을 내려받는다
   ↓
업로드 화면에서 파일을 고르고 **대상 연도**를 지정한다
   ↓  ⚠️ 기간은 화면이 계산하지 않는다. 연도를 보내면 백엔드가 기간으로 바꾼다.
검증 → 저장
   ↓
결과 화면: 원본 · 적재 · 미적재 · 설명되지 않는 행
```

업로드 한 번이 **배치(batch)** 하나입니다. 적재된 구매 행은 그 배치에 매달리고,
적재되지 않은 행은 사유와 함께 같은 배치 아래 기록됩니다.

## 1.1 결과에서 확인하는 네 숫자

```
원본 행 2,292건 · 검토 대상 적재 2,162건 · 미적재 130건 · 설명되지 않는 행 0건
```

| 숫자 | 뜻 |
|---|---|
| 원본 행 | 파일에서 읽어 Importer 에 넘긴 행 수. **세어서 기록**합니다 |
| 적재 | DB-1 에 들어가 검토 대상이 된 행 수 |
| 미적재 | 적재되지 않아 **사유와 함께 기록**된 행 수 |
| 설명되지 않는 행 | 원본 − 적재 − 미적재. **0 이 아니면 행이 사라진 것** |

⚠️ 원본 행 수는 적재 + 미적재로 되계산하지 않습니다. 그러면 "설명되지 않는 행"
이 늘 0 이 되어 아무것도 검증하지 못합니다.

# 2. 같은 달을 다시 올리면

같은 기간의 파일을 다시 올리면 **이전 배치가 대체**됩니다(D-25 확정).

| 대상 | 어떻게 되나 |
|---|---|
| 이전 배치 | `SUPERSEDED` — 행을 지우지 않고 **상태만** 바꿉니다 |
| 이전 배치의 구매 행 | 그대로 남되 계산·검토에서 빠집니다 |
| 이전 배치의 미적재 기록 | 그대로 남되 현재 집계·화면·CSV 에서 빠집니다 |
| 새 배치 | `ACTIVE` — 지금 쓰이는 배치 |
| 다른 달 배치 | **영향 없음** |

> 🔴 **STEP 12 에서 실제로 틀렸던 부분입니다.** 적재 행은 대체된 배치를 빼고
> 세는데 미적재 기록은 전부 세어, 재업로드할수록 미적재 건수만 불어났습니다.
> STEP 13 에서 두 쪽을 같은 기준으로 맞췄고, STEP 14 에서 회귀 테스트로
> 고정했습니다.

## 2.1 실측 (실데이터 2,292행을 월별로 나눠 순차 업로드)

| 기간 | 원본 | 적재 | 미적재 | 설명 안 됨 | 상태 |
|---|---:|---:|---:|---:|---|
| 2025-12 | 5 | 5 | 0 | 0 | 현재 |
| 2026-01 | 344 | 316 | 28 | 0 | 현재 |
| 2026-02 | 450 | 414 | 36 | 0 | 현재 |
| 2026-03 | 499 | 471 | 28 | 0 | 현재 |
| 2026-04 (1차) | 569 | 539 | 30 | 0 | **대체됨** |
| 2026-04 (재업로드) | 569 | 539 | 30 | 0 | 현재 |
| 2026-05 | 423 | 415 | 8 | 0 | 현재 |
| 2026-06 | 2 | 2 | 0 | 0 | 현재 |
| **전체(현재 기준)** | **2,292** | **2,162** | **130** | **0** | — |

4월을 다시 올려도 전체 숫자는 **그대로**입니다. 대체된 배치는 이력에 그때의
숫자를 그대로 간직한 채 남고, 다른 달은 손대지 않습니다. 미적재 기록은
전부 160건이 저장되어 있고 그중 **현재 유효한 것이 130건**입니다.

# 3. 업로드 이력

`GET /imports/batches` — 최근 업로드 순.

```
기간                     파일                      업로드일시            원본  적재  미적재  설명안됨  상태
2026-04-01 ~ 04-30      2026-04 원본(재업로드).xlsx  2026-08-22 06:41:29   569   539     30       0   현재
2026-04-01 ~ 04-30      2026-04 원본.xlsx           2026-08-22 06:41:27   569   539     30       0   대체됨
2026-03-01 ~ 03-31      2026-03 원본.xlsx           2026-08-22 06:41:26   499   471     28       0   현재
```

* **상태는 기존 배치 lifecycle 값 그대로**입니다 — `ACTIVE` / `SUPERSEDED`.
  ⛔ 새 상태값을 만들지 않았습니다. 화면의 "현재/대체됨" 도 백엔드가 준
  `is_current` 를 그대로 읽습니다.
* `[상세]` 를 누르면 그 업로드의 원본·적재·미적재와 **사유별 건수**가 나옵니다
  (`GET /imports/batches/{id}`).
* ⛔ **배치 삭제·복구 기능은 만들지 않았습니다.**

## 3.1 원본 행 수를 모르는 배치

`source_row_count` 는 STEP 14 부터 기록합니다. 그 전에 만들어진 배치는 값이
`null` 이고, 화면에도 `-` 로 나옵니다. ⛔ **0 으로 채우지 않습니다** — 0 건이
아니라 "모른다" 이기 때문입니다.

# 4. 미적재 행 확인

원본에는 있으나 현재 검토 대상에 포함되지 않은 행입니다.

| 수단 | 무엇 |
|---|---|
| 검토 화면 상단 안내 | 원본 대비 건수와 사유 |
| `[미적재 행 확인]` | 검색 · 사유 필터 · 정렬 · 페이지 (`GET /imports/rejections`) |
| `[미적재 CSV 내려받기]` | 원본 대조용 파일 (`GET /imports/trace.csv`) |

## 4.1 조회 조건

| 조건 | 값 |
|---|---|
| 검색 | 적요 · 거래처명 · 사업자번호 · 원본 행 번호 (띄어쓰기 무시) |
| 사유 | 사유 코드 또는 전체 |
| 정렬 | 원본 행 번호 · 금액 · 적요 · 거래처명 · 사유 |
| 방향 | 오름/내림. **값이 없는 행은 양쪽 모두에서 마지막** |
| 페이지 | 기본 50건, 최대 500건 |

⛔ **조회 기능일 뿐입니다.** 걸러 본다고 그 행이 실적에 포함되거나 빠지지
않습니다. 미적재 행을 승인·제외·검토 대상 전환하는 기능은 **없습니다**.

## 4.2 원본 행 번호는 파일마다 1부터 다시 시작한다

여러 달을 올려 두면 행 번호가 겹칩니다. 그래서 화면과 CSV 모두 **업로드 배치**
를 함께 보여 주고, 기본 정렬도 (배치, 행 번호) 순입니다 — 두 결과를 나란히
놓고 대조할 수 있도록.

## 4.3 기간으로 좁혀 보기 (STEP 15)

`[기간 ▾]` 에서 한 달을 고르면 그 달의 **현재 배치**만 봅니다. 검색·사유·정렬·
페이지와 함께 걸리고, **CSV 도 같은 조건**으로 내려옵니다(페이지만 제외).

선택지는 `GET /imports/periods` 가 줍니다. ⛔ 화면이 달을 만들지 않습니다.

## 4.4 검토 화면의 기간 선택

검토 화면 맨 앞에 `[기간 ▾]` 이 있습니다.

| 항목 | 동작 |
|---|---|
| 기본값 | **전체** — ⛔ 최신 달을 자동으로 고르지 않습니다 |
| 한 달 선택 | 그 기간의 **현재 배치**만. 대체된 배치는 나오지 않습니다 |
| 다른 조건 | 검색·상태·확정여부·과거이력·후보수·정렬·페이지와 **AND** |
| 확정 · Undo 후 | 기간·검색·필터가 **그대로 유지**됩니다 |
| 진행률 | 전체 진행률과 **선택한 기간의 진행률**이 따로 나옵니다 |
| 업로드 직후 | 새 달이 생기면 선택지가 **서버에서 다시 읽혀** 나타납니다 |
| 조회 상태 | 기간·검색·필터·정렬·페이지가 **URL 에 남습니다**(STEP 16) — 새로고침·뒤로가기·링크 공유로 같은 화면이 재현됩니다 |
| 진행 상황 | 선택지에 `2026-03 · 40 / 471` 처럼 확정/검토대상이 함께 나옵니다 |

## 4.5 CSV 의 목적

담당자가 **원본 엑셀과 나란히 놓고 눈으로 대조**하기 위한 파일입니다. 그래서
원본 행 번호와 원본 값(음수 금액 포함)을 그대로 싣고, 앞쪽 열 순서를 원본
시트에 맞췄습니다. 사양은 `IMPORT_TRACE_DESIGN.md` §5.1.

⛔ 실적 계산용도, "제외 목록" 도 아닙니다.

# 5. 지켜지는 약속 (테스트로 고정)

1. 원본 행 = 적재 + 미적재 + 설명되지 않는 행
2. 설명되지 않는 행이 있으면 테스트가 실패한다
3. 재업로드 후에는 **현재 배치 기준**으로만 적재/미적재가 계산된다
4. 이전 배치의 기록은 삭제되지 않는다
5. 다른 기간의 배치는 영향을 받지 않는다
6. 대체된 배치의 구매 행은 현재 검토 목록에 나타나지 않는다
7. 과거 미적재 기록이 현재 집계에 포함되지 않는다
8. 미적재 CSV 와 화면의 건수가 일치한다
9. 미적재 CSV 와 목록의 (배치, 원본 행 번호)가 순서까지 일치한다
10. 올리지 않은 기간의 데이터는 새 업로드로 변하지 않는다

## 5.1 기간 필터 (STEP 15 추가)

11. 기간을 고르면 그 기간의 **현재 배치**만 조회된다
12. 대체된 배치는 기간 선택지에 나오지 않고, 그 배치 ID 로 물어도 0건이다
13. 기간은 기존 조건과 AND 로 걸리고, 기존 조건의 동작은 바뀌지 않는다
14. 미적재 목록과 CSV 가 같은 조건으로 움직인다(페이지만 CSV 에서 제외)
15. 확정·Undo 후에도 고른 기간이 유지된다

## 5.2 조회 상태·진행률 (STEP 16 추가)

16. 조회 조건이 URL 에 남고, 새로고침·뒤로가기·링크 공유로 재현된다
17. 기간이 없으면 **전체**다 — 최신 달을 자동으로 고르지 않는다
18. 쓸 수 없는 URL 조건은 무시하고 **그 사실을 알린다**
19. 진행률 분모는 **적재 건수**다 — 미적재 행을 더하지 않는다(Q5-8)
20. 대체된 배치의 확정 이력이 진행률에 섞이지 않는다
21. 확정·Undo 뒤 선택지 글자와 보조 정보가 **같은 숫자**를 말한다

## 5.3 키보드 조작·미적재 사유 요약 (STEP 17 추가)

22. 어떤 키도 확정·확정 취소를 실행하지 않는다 — 키는 이동과 포커스뿐이다
23. 현재 행은 화면 상태다 — DB·URL·lifecycle 어디에도 남지 않는다
24. 행을 옮겨도 서버 요청이 생기지 않는다
25. 입력창·선택상자 안에서는 단축키가 동작하지 않고 기본 동작이 살아 있다
26. 확인창 안에서 `Tab` 이 밖으로 새지 않고, 닫으면 원래 자리로 돌아온다
27. 기간별 미적재 사유가 **현재 배치 기준**으로 사유별로 나뉘어 표시된다
28. 사유 코드·이름을 화면이 만들지 않는다 — 사유가 늘면 줄만 늘어난다
29. 사유 요약은 사실 표시다 — "제외" · "검토 불필요" 를 뜻하지 않는다

# 7. 아직 결정되지 않은 것

| 항목 | 상태 |
|---|---|
| 금액 ≤ 0 행을 검토 대상에 포함할지 | 🔴 Q5-8 확인 대기 |
| 실적으로 인정할지 | 🔴 확인 대기 |
| DB-1 에 저장할지 | 🔴 확인 대기 (저장 규칙 변경 · PM 승인 사항) |
| 계산에 포함할지 | 🔴 DB-3 · Calculator 미착수 |
| 구매유형 업무규칙 · 분석 방법 · 자동확정 · 임계값 · 그룹핑 | 🔴 전부 미정 |

> ⚠️ **키보드 조작은 UI 편의 기능입니다.** 자동확정이 아니며, 구매유형을
> 시스템이 판단하지 않습니다. **미적재 사유 요약도 사실 표시일 뿐**이고,
> 미적재 행의 업무 처리 방식은 아직 확정되지 않았습니다(Q5-8).

**미적재 행은 현재 업무규칙이 확정되지 않은 상태이므로, 시스템이 실적 인정
여부나 검토 필요 여부를 판단하지 않습니다.** 원본에 있었다는 사실과 적재되지
않은 사유만 기록해 두고, 판단은 고객 답변 이후로 미룹니다.
