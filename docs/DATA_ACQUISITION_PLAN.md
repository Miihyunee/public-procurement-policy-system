### 2.1.1 현재 코드가 요구하는 필드 (5개)

> ④의 요청 양식에서 **선택 항목으로 함께 요청**한다.

| 형식 | 적합성 | 비고 |
|---|---|---|

| **CSV (UTF-8)** | 🟢 권장 | 인코딩 명시 필요. 사업자번호를 **텍스트로 보존**하기 쉬움 |

### 2.2.0.1 🔴 확인된 제약 — 여성·장애인 API 는 기업 정보를 주지 않는다

`getFnrssList` · `getDspsnList` 응답에는 **기업명·대표자명·사업자번호가 없다.**
유효기간과 인증기관만 온다. 따라서 이 두 정책은 API 만으로 `Company` 를 만들 수 없다.

| 필요 값 | 확보 경로 |
|---|---|
| `business_no` | 요청에 사용한 값을 그대로 사용 (구매데이터에서 옴) |
| `company_name` | **구매데이터의 공급업체명** 사용 가능 |
| `representative_name` | ❌ **없음** → `Company.representative_name` 필수 제약(B-4) 해소 필요 |

> ⚠️ **`stdrDate`(기준일자)가 필수**다. "유효확인서를 확인할 기준일자" 이므로,
> 어느 시점을 넣느냐에 따라 조회 결과가 달라질 수 있다. 어떤 기준일로 조회할지는
> **실제 호출로 동작을 확인한 뒤** 정한다. 추측하지 않는다.

### 2.2.0.2 연동 계층 구현 현황 (2026-08-14)

호출 계층을 구현했다. 계층 분리는 다음과 같다.

```
Transport → ApiClient → Parser → Certification
```

| 계층 | 모듈 | 상태 |
|---|---|---|
| 전송 | `collectors.transport` | ✅ 구현 (표준 `urllib`, 외부 의존성 없음) |
| 호출 | `collectors.client` | ✅ 구현 (엔드포인트·키·파라미터·재시도·오류 분류) |
| 해석 | `collectors.smpp` · `collectors.kised` | ✅ 기존 파서 **재사용** (변경 없음) |
| 저장 | `collectors.sync_service` | ✅ 기존 `Certification` 에 연결 |

**오류 범주 구분**

| 범주 | 재시도 |
|---|---|
| timeout · 네트워크 오류 · HTTP 5xx | ✅ 대상 |
| 인증 실패(결과코드 `20`/`30`/`32`) · 잘못된 요청 · 한도 초과(`22`) | ❌ 금지 |
| 정상 응답 + 데이터 없음(`03`) | 오류 아님 — 빈 목록 |

> 🔴 **실호출은 검증되지 않았다.** 개발 환경에서 `apis.data.go.kr` 로의 접근이
> 차단되어 있어(HTTP 403 — egress 차단), 실제 인증키로 응답을 받아본 적이 없다.
> 위 표의 "구현"은 **명세서 샘플 구조를 대역(stub)으로 검증했다**는 뜻이며,
> **운영 연동 완료를 의미하지 않는다.**

> ⛔ **`stdrDate` 는 코드가 정하지 않는다.** 호출자가 명시적으로 전달해야 하며,
> 생략하면 `StdrDateRequiredError` 가 난다. 오늘 날짜·연도 말일·지급일·계약일
> 어느 것도 기본값으로 쓰지 않는다.

> ⛔ **기업이 등록되어 있지 않으면 인증을 저장하지 않는다.** `Company` 는
> `company_name`·`representative_name` 이 필수인데 여성·장애인 확인 API 는 둘 다
> 주지 않는다(§2.2.0.1). 없는 값을 지어내지 않고 `COMPANY_NOT_FOUND` 로 보고한다.

| `22` | 일일 한도 초과 | `ApiQuotaError` (재시도 금지) |
| 그 밖의 코드 | 명세에 없음 | 추측하지 않고 `ApiResponseError` 로 남김 |
| HTTP 4xx | 잘못된 요청 | `ApiRequestError` (재시도 금지) |
| HTTP 5xx · timeout · 네트워크 | 일시적 장애 | 재시도 대상 (기본 2회) |

**현재 구현 범위**

```
사업자등록번호 → 요청 → 응답 → 파싱 → CertificationRecord 반환
```

여기까지다. 조회 계층은 `Repository` 를 import 하지 않으며 DB 를 건드리지 않는다.

**아직 결정하지 않은 사항**

| # | 항목 | 상태 |
|---|---|---|
| 1 | **인증 유효기간 판정 기준일** | 🔴 고객 미확인 — `valid_from`·`valid_to` 를 읽기만 하고 비교하지 않는다 |
| 2 | 창업기업 정식 출처 (SMPP / 창업진흥원 2종 중) | 🔴 미정 — 코드가 한쪽을 기본으로 고르지 않는다 |
| 3 | `earlyValidPdDe`(초기창업자기간)의 취급 | 🔴 미정 |
| 4 | 인증 상태(정상/취소/정지) | 이 API 는 제공하지 않음 — 취소 인증 식별 불가 |
| 5 | **엔드포인트 `http` / `https`** | 🟡 명세서 기재는 `http`. 인증키가 질의문자열로 평문 전송된다. `https` 지원 여부는 실호출로만 확인 가능하며 추측해서 바꾸지 않았다 |

> ⛔ **가져오는 것과 판정하는 것을 섞지 않는다.** 확인서가 조회됐다는 이유로
> `창업기업 = True`, 유효기간이 오늘을 포함한다는 이유로 `유효 = True` 를 만들지
> 않는다. 기준일이 확정된 뒤 별도 단계에서 구현한다.

> `apis.data.go.kr` 로의 접근이 차단되어 있다(`http` → 403, `https` → 연결 실패).
> 인증키가 있어도 이 환경에서는 실제 응답을 받을 수 없다.

### 2.2.0.5 창업기업 API 결과코드 `90` 처리 기준 (2026-08-27)

> ⚠️ **이 코드는 공식 활용가이드에 기재되어 있지 않다.** 이 사실을 지우지 않는다.

| 항목 | 내용 |
|---|---|
| 발견 경위 | 2026-08-27 `smppKiCertInfo/getKiCertInfo` **실호출** |
| 실제 메시지 | `매칭데이터가 존재하지 않습니다.` |

**왜 이렇게 처리하는가.** 이 코드가 오기 전까지 시스템은 명세에 없는 코드를
추측하지 않고 오류로 올렸다. 그 결과 **확인서가 없는 기업을 조회할 때마다 오류가
나 대량 조회 운영이 불가능**했다. 확인서 미보유는 정상적인 상태이지 장애가 아니다.

**`00` 과 무엇이 다른가.**

| 코드 | 뜻 | 동작 |
|---|---|---|
| `00` | 정상 · **데이터 있음** | 항목을 해석해 확인서 목록을 만든다 |
| `03` | 정상 · 데이터 없음 (명세 기재) | 빈 목록 |
| **`90`** | 정상 · 데이터 없음 (**실호출 확인**) | 빈 목록 — **항목을 보지 않는다** |
| `20`·`30`·`32` | 인증 오류 | 예외 (재시도 금지) |
| `22` | 한도 초과 | 예외 (재시도 금지) |
| 그 밖 | 명세에 없음 | **추측하지 않고** 예외 |

⛔ `90` 을 `00` 으로 바꾼 것이 **아니다.** 빈 목록을 돌려줄 뿐이며, `Certification`
레코드를 만들지 않고 "창업기업 해당" 같은 판정도 하지 않는다.

⛔ **여성기업·장애인기업에는 적용하지 않았다.** 그 API 들의 응답에서 같은 숫자가
무슨 뜻인지 확인된 바가 없다. 확인하지 않은 API 까지 넓히면 진짜 오류를 조용히
삼키게 된다.

# ④ 고객 구매데이터 요청사항

> **고객 파일을 임의로 만들지 않았다.** 아래는 **요청 항목 정의**이며 샘플 데이터가 아니다.

## 4.1 고객 전달용 요청문 (그대로 사용 가능)

> **우선구매 정책 달성률 검증을 위해 아래 항목이 포함된 구매실적 데이터를 요청드립니다.**
>
> - 대상 기간: **1개 회계연도 전체** (부분 기간은 비율 계산이 왜곡됩니다)
> - 대상 범위: **해당 기간의 전체 구매 건** (정책 대상만 골라내지 말고 전체)
> - 파일 형식: **Excel(.xlsx) 또는 CSV(UTF-8)**
> - **사업자등록번호는 반드시 텍스트 형식으로** 저장해 주십시오
>   (숫자로 저장하면 앞자리 `0` 이 사라져 매칭에 실패합니다)

## 4.2 필수 항목

| # | 항목 | 왜 필요한가 |
|---|---|---|
| 1 | **사업자등록번호** | 기업·인증 정보와 연결하는 **유일한 결합 키**. 없으면 어떤 정책 판정도 불가 |
| 2 | **계약일** | **창업기업** 정책의 판정 기준일 |
| 3 | **지급일**(지출완료일) | **중소기업·여성기업·장애인기업** 등의 판정 기준일 |
| 4 | **구매금액** | 정책별 실적과 전체 구매액(분모) 산출의 기준 |
| 5 | **공급업체명** | 매칭 실패 시 원인 확인용. 사람이 검증할 때 필수 |

> ⚠️ **2와 3은 둘 다 필요합니다.** 정책마다 판정 기준일이 다르기 때문에 한쪽만 있으면
> 해당 기준을 쓰는 정책의 실적이 누락됩니다.
