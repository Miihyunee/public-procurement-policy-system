## 3.1 [결정 A] 매뉴얼에 「인증키 발급받기」 절을 넣을 것인가

**현황**

기업정보를 **API 로 조회해서 등록하는 기능**이 이미 구현·배선되어 있습니다.
여성기업 · 장애인기업 · 창업기업 3종이 대상입니다.

| | 파일 업로드 | API 조회 |
|---|---|---|
| 대상 정책 | 8종 전부 | **여성 · 장애인 · 창업** 3종 |
| 넣는 것 | 명단 파일 전체 | 사업자등록번호를 직접 입력 |
| 인터넷 | 불필요 | **필요** |
| 별도 준비 | 없음 | **인증키** |
| 저장 이후 | 동일 | 동일 |

**문제**

사용자 매뉴얼은 **키를 어디에 넣는지**(`.env` 위치와 형식)는 적어 두었으나,
**키를 어떻게 발급받는지**는 「담당자에게 문의해 주십시오」로 넘깁니다.

- `data.go.kr` · 활용신청 · Decoding 키 같은 말이 매뉴얼에 한 번도 없습니다.
- 어느 API 를 신청해야 하는지 목록이 없습니다.
- → **고객이 매뉴얼만 보고 이 기능을 켤 수 없습니다.**

발급 절차 자체는 이미 조사돼 저장소에 있습니다
(`EXTERNAL_API_ONBOARDING.md` — 신청 URL·방식·키 종류까지 정리됨).
다만 그것은 **개발자용 문서**이고 고객에게 전달되지 않습니다.

**결정 요청**

| 안 | 내용 | 비용 |
|---|---|---|
| A-1 | 사용자 매뉴얼 8장에 「인증키 발급받기」 절 추가 + PDF 재생성 | 작음 |
| A-2 | 매뉴얼은 그대로 두고, 기관 담당자에게 별도 1쪽 안내문 전달 | 매우 작음 |
| A-3 | 손대지 않는다 (조회 기능은 사실상 안 쓰는 것으로 둔다) | 없음 |

> 참고: 조회 기능은 **명단 전체를 받는 기능이 아닙니다.** 번호를 하나씩
> 넣어 확인하는 방식이라 기관 전체 명단을 채우는 데는 쓸 수 없습니다.
> 실제 쓸모는 **미매칭 기업 몇 곳 확인**·**명단 없는 정책 임시 보완**입니다.
> 그 점을 고려해 판단해 주십시오.

## 3.2 [결정 B] 구매실적 업로드를 표준 양식 밖에서도 받을 것인가

**현황**

| 자료 | 원본 양식 그대로 되나 |
|---|---|
| 기업정보 명단 | ✅ **된다** — 머리글 별칭 대응 있음 |
| 구매실적 | ❌ **안 된다** — 표준 양식 9칸 필요 |

기업정보 명단은 실제 여성기업 원본에서 확인한 대응을 넣어 두었습니다.

```
업체명 → 기업명   사업자번호 → 사업자등록번호
시작일자 → 유효시작일   만료일자 → 유효종료일
```

구매실적에는 별칭이 없습니다. **기관의 실제 구매실적 원본 머리글을 아직
확인하지 못했기 때문입니다.** 짐작해서 넣으면 엉뚱한 칸이 조용히 금액으로
읽힐 수 있어 넣지 않았습니다.

**담당자 의견**: 「양식과 다르면 양식에 맞춰야 하는 게 불편하다.」

**결정 요청**

기관이 실제로 쓰는 **구매실적 원본 파일의 머리글 한 줄**(값은 불필요)을
확보해 주시면, 기업정보와 동일한 방식으로 별칭을 넣어 **양식 변환 없이 바로
업로드**하게 만들 수 있습니다.

| 안 | 내용 |
|---|---|
| B-1 | 원본 머리글을 확보한 뒤 별칭 추가 (**권고**) |
| B-2 | 지금처럼 표준 양식 유지 — 담당자가 매번 변환 |

⛔ 머리글을 확보하기 전에는 별칭을 추측으로 넣지 않습니다.
