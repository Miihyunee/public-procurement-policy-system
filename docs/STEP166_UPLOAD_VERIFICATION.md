## A. 빌드 절차 (개발용 Windows PC)

PyInstaller 는 크로스 컴파일을 하지 않으므로 **Windows 에서** 실행해야 합니다.

### A-1. 소스 최신화

```powershell
cd <저장소 경로>
git fetch origin claude/period-filter-import-batch
git checkout claude/period-filter-import-batch
git pull origin claude/period-filter-import-batch
git log --oneline -1
git status --short
```

확인할 값

- `git log --oneline -1` → `1a8cd3a feat: show what an upload will change before it is saved`
- `git status --short` → 출력 없음(clean)

### A-2. 백엔드 빌드 (PyInstaller)

```powershell
.\.venv\Scripts\activate
pyinstaller packaging/procurement-backend.spec
Get-FileHash .\dist\procurement\procurement.exe -Algorithm SHA256
```

확인할 값

- `dist\procurement\procurement.exe` 생성
- SHA-256 값 (뒤 A-4 에서 설치본 안 파일과 대조)

### A-3. 설치본 빌드 (electron-builder)

```powershell
npx electron-builder --win --config.electronDist="$env:LOCALAPPDATA\ebtmp\unpacked"
```

확인할 값

- 출력 폴더는 `release\` 입니다(`dist\` 아님).
- `release\공공구매정책관리시스템 Setup 0.1.0.exe` 생성
- 파일 크기와 SHA-256

### A-4. 설치본 안 백엔드 대조

```powershell
Get-FileHash "release\win-unpacked\resources\backend\procurement.exe" -Algorithm SHA256
```

확인할 값

- A-2 의 SHA-256 과 **같아야** 합니다. 다르면 설치본에 옛 백엔드가
  들어간 것이므로 A-2 부터 다시 합니다.

### A-5. 설치본 버전 확인 방법 (UI 로 판별)

백엔드는 이번에 바뀌지 않았으므로(파이썬 변경 0), **화면으로** 판별합니다.
프로그램을 실행해 「자료 관리」 탭의 구매실적 업로드 카드에서 다음 두 가지가
보이면 최신 설치본입니다.

1. 「**1 파일 고르기 → 2 검증 → 3 저장**」 단계 표시가 있다.
2. 대상 월 기본값이 「**연 전체**」다. (옛 설치본은 이번 달이 기본값)

## B. 고객 PC 검증 절차

각 단계마다 **그 단계의 확인 결과만** 받고 다음으로 넘어갑니다.

### B-1. 최신 설치본 설치

- 실행: `공공구매정책관리시스템 Setup 0.1.0.exe`
- 서명이 없어 SmartScreen 경고가 뜹니다 → [추가 정보] → [실행]
- ⛔ 기존 프로그램을 먼저 지우지 않습니다. 덮어 설치해도 고객 데이터
  (`%APPDATA%`)는 지워지지 않습니다.
- **확인 결과** — 설치 완료 여부, 설치 경로

### B-2. 프로그램 실행

- 바탕화면 아이콘으로 실행
- **확인 결과** — 화면이 뜨는지, 단계 표시(1·2·3)가 보이는지,
  대상 월 기본값이 「연 전체」인지 (= 최신 설치본 확인)

### B-3. 업로드 전 현재 배치 확인

- 「자료 관리」 탭 → 구매실적 업로드 카드의 「지금 등록되어 있는 자료」
- 업로드 이력 표도 함께 확인
- **확인 결과(기록)**
  - 배치 번호
  - 기간(period_start ~ period_end)
  - 상태(ACTIVE / SUPERSEDED)
  - 파일명
  - 행 수

### B-4. 원본 파일 선택

- [파일 선택] → 회계시스템에서 받은 **원본 엑셀 그대로** 고릅니다.
  ⛔ 열어서 저장하거나 이름을 바꾸지 않습니다.
- 대상 연도 = 2026, 대상 월 = **연 전체**
- **확인 결과** — 화면에 표시된 파일명, 단계가 「2 검증」으로 넘어갔는지,
  [검증하고 저장하기]가 아직 잠겨 있고 「검증을 먼저 실행하세요.」가
  적혀 있는지

### B-5. 검증 실행

- [검증만 하기] 를 누릅니다. (⛔ 저장 아님)
- **확인 결과** — 처리 중 표시 후 결과가 나오는지

### B-6. 검증 결과 확인

- **확인 결과(기록)**
  - 배지 — 「검증 통과」 / 「확인 필요」
  - 총 행 수
  - 정상 행 수
  - 오류 행 수
  - 자동 제외 안내 — 집계 행 / 앞선 해 결의 건 / 기간 외 건
  - 안내 문장 전문
- 오류 행이 있으면 여기서 멈추고 PM 에게 보고합니다.

### B-7. 저장 또는 교체 확인

- [검증하고 저장하기] 를 누릅니다.
- 같은 기간에 등록된 자료가 있으면 **교체 확인창**이 뜹니다.
- **확인 결과(기록)** — 확인창에 적힌 다섯 줄을 그대로
  - 지금 저장된 자료
  - 새로 올리는 자료
  - 대상 기간
  - **함께 교체되는 등록** (없으면 「없습니다」)
  - 그대로 두는 것
- 내용이 예상과 다르면 **[취소]** 를 누르고 보고합니다.
  취소해도 기존 자료는 그대로입니다.
- 맞으면 [교체하고 저장하기] 를 누릅니다.

### B-8. 저장 완료 결과 확인

- **확인 결과(기록)**
  - 배지 — 「저장 완료」
  - 저장 행 수
  - 새 배치 번호
  - 안내 문장 전문

### B-9. 재조회로 실제 상태 확인

⛔ 화면 표시만으로 교체를 판정하지 않습니다. **재조회 결과**로 확인합니다.

```powershell
$port = <프로그램이 쓰는 포트>
curl.exe -s "http://127.0.0.1:$port/imports/batches"
curl.exe -s "http://127.0.0.1:$port/dashboard/data-status"
```

- **확인 결과(기록)**
  - 새 배치 — 번호 · 기간 · 상태 `ACTIVE` · 행 수
  - 이전 배치 — 상태가 `SUPERSEDED` 로 바뀌었는지
  - 구매실적 건수가 늘었는지
