# 0. 표기 원칙 (중요)

본 문서는 **세 가지 출처를 엄격히 구분**한다.

| 표기 | 의미 |
|---|---|
| **[파일]** | 첨부된 2026년 정부권장정책 파일에서 **직접 확인된 내용** |
| **[프로젝트]** | 기존 프로젝트 문서·코드의 설계 내용 (파일 근거 아님) |
| **`미확인`** | 파일에도 없고 프로젝트에서도 확정되지 않은 사항 |

> ⚠️ 파일에 없는 내용을 사실처럼 기술하지 않는다.
> 특히 **판정 기준일·사업자등록번호 요구 여부는 파일에 기재되어 있지 않다.**

# 3. MVP에 있으나 파일에서 확인되지 않는 정책 (지시 3번)

## 3.1 녹색제품 (`GREEN`) — ⚠️ 파일 미확인

| 항목 | 내용 |
|---|---|
| **[파일] 등장 여부** | **없음.** 구매 11개 항목·채용 4개 항목 어디에도 "녹색제품" 표기 없음 |
| **[프로젝트] 근거** | `POLICY_DEFINITION.md` 에 MVP 5종 중 하나로 정의, `bootstrap.py` 가 `GREEN` 으로 seed |
| **[프로젝트] 기존 판단** | 판정 단위(기업/제품) 미확정 → **"추가 업무 분석 필요"** 상태 (R-1) |

### 별도 정책으로 유지할 근거 분석 (지시 9번)

| 관점 | 판단 |
|---|---|
| **본 파일 기준** | ❌ **근거를 찾을 수 없음.** 2026년 정부권장정책 목록에 없음 |
| 프로젝트 문서 기준 | 🟡 `POLICY_DEFINITION.md` 에는 있으나, 그 문서의 출처가 무엇인지 `미확인` |
| 제도 자체의 존재 | `미확인` — 녹색제품 의무구매 제도가 **다른 근거 법령/지침**에 존재할 가능성은 본 파일로 판단 불가 |

### 가능한 해석 (셋 다 파일만으로는 확정 불가)

| 해석 | 설명 |
|---|---|
| ① 별도 제도 | 녹색제품은 **정부권장정책이 아닌 별도 제도**(환경 관련 법령)로 관리될 수 있음 |
| ② 파일 범위 한정 | 본 파일이 **정부권장정책만** 다루고 다른 제도를 포함하지 않을 수 있음 |
| ③ 2026년 제외 | 2026년 기준에서 정부권장정책 항목으로 관리되지 않을 수 있음 |

> **결론**: 본 파일만으로는 **녹색제품을 MVP에 유지할 근거를 확인할 수 없다.**
> 유지·제외 판단에는 **녹색제품 의무구매의 근거 자료**가 별도로 필요하다 → **PM 결정 필요**.

# 5. Calculator 동일 방식 계산 가능 여부 (지시 5·6번)

# 6. 여성기업 — 구매유형별 목표율 처리 가능 여부 (지시 7번)

## 6.1 [파일] 요구사항

> **7. 여성기업(총 구매금액의 공사 3% 이상 및 용역·물품 5% 이상)**

즉 **하나의 정책에 목표율이 2개**이며, 구매유형에 따라 달라진다.

| 구매유형 | 목표율 |
|---|---|
| 공사 | 3% |
| 용역·물품 | 5% |

## 6.2 현재 데이터 모델로 처리 가능한가 — ❌ **불가능**

| 필요 요소 | 현재 상태 |
|---|---|
| 정책당 **복수 목표율** | ❌ `Policy.target_rate` 는 **단일 `Decimal`** |
| 구매건의 **구매유형 구분** | ❌ `Purchase` 에 **구매유형 필드 없음** (`business_no`·`company_name`·`contract_date`·`payment_date`·`amount` 뿐) |
| 유형별 **분모 분리** | ❌ Calculator 는 전체 구매금액 단일 분모만 사용 |

## 6.3 추가로 필요한 것 (분석)

| # | 필요 작업 | 영향 범위 |
|---|---|---|
| 1 | `Purchase` 에 **구매유형(공사/용역/물품)** 필드 추가 | 모델·DB·Import·매핑 문서 |
| 2 | 정책별 **복수 목표율** 구조 (예: `PolicyTargetRate` 테이블) | 모델·DB·Repository |
| 3 | Calculator 가 **유형별로 분리 집계** | 계산 로직 |
| 4 | Dashboard 응답에 **유형별 달성률** 표현 | API DTO |

> ⚠️ **고객 구매데이터에 구매유형 구분이 있는지 `미확인`.**
> 없다면 여성기업은 **어떤 구조를 만들어도 계산할 수 없다.**
> → **구매데이터 수신 시 최우선 확인 항목**으로 추가해야 한다.

# 7. 국가유공자자활용사촌 — 다른 분모 처리 가능 여부 (지시 8번)

## 7.1 [파일] 요구사항

> **11. 국가유공자자활용사촌(자활용사촌 생산가능품목 총 구매액의 7% 이상)**

분모가 **"자활용사촌 생산가능품목 총 구매액"** 이다. 전체 구매금액이 아니다.

## 7.2 현재 계산 구조로 처리 가능한가 — ❌ **불가능**

현재 Calculator 는 분모를 `calculate_total_purchase()`(전체 합계)로 **고정**한다.
분모를 정책별로 바꾸는 수단이 없다.

### 구조적 난점

| # | 문제 | 설명 |
|---|---|---|
| 1 | **분모 자체가 품목 기준** | "생산가능품목"에 해당하는 구매만 골라 합산해야 함 |
| 2 | **품목 정보 없음** | `Purchase` 에 품목·물품목록번호 필드 없음 |
| 3 | **생산가능품목 목록 필요** | 어떤 품목이 대상인지 판단할 기준 데이터 필요 (`미확인`) |
| 4 | 분자·분모가 **같은 품목 집합** 기반 | 기업 인증만으로는 계산 불가 |

## 7.3 동일 유형 정책

**분모가 다른 정책은 자활용사촌만이 아니다.**

| 정책 | 분모 | 필요 데이터 |
|---|---|---|
| 3. 기술개발생산품 | 중소기업생산품 구매액 | **중소기업 실적 계산 결과**(정책 간 의존) + 제품 식별 |
| 6. 온누리상품권 | 기관 경상경비 금액 | **경상경비 총액**(구매데이터에 없음) |
| 11. 자활용사촌 | 생산가능품목 총 구매액 | 품목 정보 + 생산가능품목 목록 |

> **3번은 특히 주의**: 분모가 **다른 정책의 계산 결과**다. 정책 간 계산 순서·의존 관계가
> 생기며, 현재 구조에는 그런 개념이 전혀 없다.

## 7.4 필요한 구조 변경 (분석)

정책별로 분모를 다르게 하려면 **분모 유형(denominator type)** 개념이 필요하다.

| 분모 유형 | 의미 |
|---|---|
| `TOTAL_PURCHASE` | 전체 구매금액 (현재 유일한 방식) |
| `POLICY_PURCHASE` | 다른 정책의 구매액 (기술개발생산품) |
| `EXTERNAL_AMOUNT` | 외부 입력 금액 (경상경비) |
| `ITEM_SCOPED` | 특정 품목군 구매액 (자활용사촌) |

## 11.1 확인된 사실

1. **구매 부문 커버리지는 11개 중 4개(36%)** 다. 7개가 누락되어 있다.
2. **여성기업은 현재 구조로 계산할 수 없다.** 목표율이 구매유형별로 2개인데,
   `Policy.target_rate` 는 단일값이고 `Purchase` 에 구매유형 필드가 없다.
   **이미 MVP에 포함된 정책이 계산 불가 상태**라는 점이 가장 시급한 문제다.
3. **분모가 총 구매금액이 아닌 정책이 3개**(기술개발·온누리상품권·자활용사촌) 있다.
   현재 Calculator 는 분모가 고정되어 있어 지원하지 못한다.
4. **녹색제품은 본 파일에서 확인되지 않는다.** MVP 유지 근거를 파일로는 확인할 수 없다.
5. **채용 부문 4개는 구매 데이터로 계산할 수 없다.** 파일도 기업리스트 활용을 `×` 로 표시한다.

## 11.2 파일로 판단할 수 없는 사항 (`미확인`)

| # | 항목 | 사유 |
|---|---|---|
| 1 | **모든 정책의 판정 기준일** | 파일에 지급일/계약일 언급이 전혀 없음 |
| 2 | 사업자등록번호 요구 여부 | 파일에 직접 기재 없음(기업리스트 ○/- 로 간접 추정만 가능) |
| 3 | 장애인표준사업장 "1000분의 8%" | 표기 자체가 모호 |
| 4 | 녹색제품 제도 존재 여부 | 파일 범위 밖 |
| 5 | 각 정책의 인증·확인 방법 | 파일에 기재 없음 |
| 6 | 목표율의 적용 연도·경과 규정 | 파일에 기재 없음 |
