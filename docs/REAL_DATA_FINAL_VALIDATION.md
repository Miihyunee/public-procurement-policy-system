**실제 고객 원본 데이터**로 사실관계를 확인한 결과를 적는다. 지금까지의 조사는


**두 규칙은 실데이터에서 서로 다른 결과를 낸다.** 어느 쪽도 129건을 혼자
해결하지 못한다.

| 사실 | 뜻 |
|---|---|
| 금액 기준으로 **85건이 후보 복수** | 금액만으로는 짝을 자동 선택할 수 없다 |
| 그중 **116건은 적요까지 같다** | 적요를 **좁히는 조건**으로 쓰면 크게 줄어든다 |
| **10건은 금액은 맞고 적요가 다르다** | 고객이 *"간혹 적요가 다를 경우가 있어 확인은 해줘야함"* 이라고 한 바로 그 경우다 |
| **3건은 대응 양수가 아예 없다** | 자동으로 처리할 수 없다 — 담당자 확인 대상 |

→ `CUSTOMER_ANSWER_IMPACT_ANALYSIS.md` §B 가 제안한 읽기(**후보 검색은 금액,
자동 상계는 적요까지 같을 때, 나머지는 담당자 확인**)가 실데이터와 모순되지
않는다는 것까지는 확인됐다.

⛔ **그러나 그것은 우리 해석이지 고객이 말한 것이 아니다.** 🔴 확인이 필요하다.

⛔ 이번 단계에서 바꾸지 않은 것: `amount <= 0` 저장 거부 · `core/offsetting.py`

## 7. STEP 84 기능 실제 데이터 검증

### 7.1 ⚠️ 전체 흐름은 **끝까지 돌리지 못했다**

실데이터를 표준 양식 머리글로 옮겨 현재 검증·적재 계층에 그대로 넣은 결과다.

| 단계 | 결과 |
|---|---|
| 머리글 검사 | 통과 (필수 컬럼 이름은 모두 만들 수 있음) |
| **행 검증** | 총 2,292 · **통과 0** · 오류 2,292행 |
| ㄴ 오류 사유 | `계약일자: 값이 없습니다` 2,292 · `지급일: 값이 없습니다` 2,292 |
| ㄴ 경고 | 133행 — 0 이하 금액 131 · 사업자등록번호 체크섬 불일치 2 |
| 적재 | **0건** (통과한 행이 없다) |
| 계산 | **불가** |

**원인은 버그가 아니라 양식과 원본의 불일치다.** 표준 양식은 계약일자·지급일을
필수로 두는데, 고객 원본에는 그 두 컬럼이 없다.

⛔ **다른 날짜로 대신 채우지 않았다.** 계약일자는 창업기업 판정에 쓰이는 값이라
(🟢 §0.6.2), 임의로 채우면 실적 숫자가 근거 없이 달라진다.

않았다.** 다만 다음은 확인됐다.

- 검증 계층은 **값을 채우지 않는다** — 빈 계약일자·지급일을 다른 날짜로
  대체하지 않고 오류로 돌려보냈다. (`uploads/mapping.py` 의 "그대로 넘긴다"
  원칙이 실데이터에서도 지켜졌다.)
- 미적재 사유가 **행 번호 · 컬럼 · 사유** 로 남는다 — 2,292행 전부 추적 가능.

⚠️ **원본 보존·이력 흐름의 실데이터 확인은 적재가 가능해진 뒤에 다시 해야
한다.** 지금 상태로는 🔴 미확인이다.

## 10. 발견된 문제

### 10.1 🔴 원본에 계약일자·지급일이 없다 (가장 큰 문제)

표준 양식의 필수 컬럼 두 개가 고객 원본에 존재하지 않는다. **현재 상태로는
실데이터를 한 행도 적재할 수 없다.**

⛔ **코드로 임의 해결하지 않았다.** 생각할 수 있는 길이 여럿이고, 어느 것도
우리가 고를 수 없기 때문이다.

| 길 | 무엇이 걸리는가 |
|---|---|
| ① 고객이 두 컬럼을 채워 준다 | 담당자 손이 든다. 애초에 그 값을 갖고 있는지 확인 필요 |
| ② 두 컬럼을 선택 항목으로 바꾼다 | **창업기업 판정(🟢 §0.6.2)이 계약일자를 쓴다** — 없으면 창업기업 실적이 빠진다 |
| ③ 결의일자로 대신 채운다 | ⛔ 다른 날짜를 계약일자라고 부르는 것이다. 근거 없는 실적이 된다 |

→ 🔴 **PM·고객 판단 필요.**

### 10.2 🟡 사업자등록번호 체크섬 불일치 2건

경고로만 처리되어 저장은 막지 않는다(현재 설계대로). 원본 오탈자인지 실제
번호인지는 확인이 필요하다. ⛔ 자동 교정하지 않는다.

### 10.3 🟡 인증 정보가 **원본 파일 안에 이미 있다**

`작업` 시트(1,744행)에 담당자가 손으로 모아 둔 인증 정보가 들어 있다.

| 컬럼 | 실제 값이 있는 행 |
|---|---|
| 업체규모 | 1,484 |
| 중소기업 기간 | 733 |
| 여성기업 | 165 |
| 창업기업 | 102 |
| 사회적기업 | 105 |
| 장애인기업 | 41 |
| 사회적협동조합 | 34 |
| 장애인표준사업장 | 0 |

⚠️ **인증 API 가 미발급인 상태에서 이 시트가 유일한 인증 자료다.** 다만
`#N/A` 가 섞여 있고(사회적협동조합 1,710행), 이 시트를 인증 원천으로 삼을지는
**업무 판단**이다.

⛔ 이 시트를 인증 데이터로 자동 적재하지 않았다. 🔴 PM 판단 필요.

### 10.4 ⚪ 구현 버그는 발견되지 않았다

이번 조사에서 **코드를 고쳐야 할 결함은 나오지 않았다.** 막힌 지점은 전부
"값이 없다" 또는 "규칙이 정해지지 않았다" 였다.
